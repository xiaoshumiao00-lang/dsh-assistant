## 0. 一页结论

**你要的东西**：屏幕上只有一个「鹈鹕」在跟你说话，你说一句话，它自己决定这件事该派给哪个项目、开哪条会话；完事了屏上有气泡、耳朵里有播报，你不用先找到那条会话再念一遍指令。

**方案要点（三条铁律）**

1. **入口唯一**：设备永远绑在一条「指挥会话」上，不再有会话选择器、不再有「自动跟随最活跃会话」。指挥会话只负责听懂＋派单＋汇报，它不干活。
2. **事实源换了**：屏幕和播报不再按「会话 id」投影，而是按「任务 id」投影。任务登记簿（Task Ledger）是唯一事实源，会话只是任务的执行载体。
3. **通知不对称固定**：任务完成 → 屏上气泡 ＋ 一句语音播报，**绝不要求你先点进某条会话**；只有「需要人回答」（决策／危险动作／歧义）才打断你。

**落点规则（本轮补齐，见 §7）**：复杂任务跟控制室的项目卡片走（一个项目文件夹下可以有 N 条会话）；控制室没有卡就新建一张、双写同步，控制室立刻可见；日常简单任务落到「个人助手」卡片（`wt-assistant`）的文件夹——和长按悬浮球的落点完全一致；追加到已有任务不新建、不乱选文件夹。

**为什么现在做不到**：代码里「注入到哪条会话」只有 `device.sessionId` 这一个单值字段（`src/tihu/lane.ts:237`、`2822-2828`），唯一的挑选逻辑是从所有 Computer Use 会话里按 `updatedAt` 挑最活跃的一条（`1085-1094`、`1296-1328`）；屏帧、右侧气泡、主页钉住、工具闸门窗口全部按会话 id 建键；控制面 12 个动作里**没有任何「新建会话／派任务」**（`src/tihu/control.ts:240-356`）。仓库里「按项目建会话并注入任务」的路径其实已经存在（`src/client/index.tsx:1885-1923`、`4327-4347`、`4386-4464`、`src/client/pocket/orb/orb-api.ts:376-419`），鹈鹕侧却没用上——本次设计就是把这条现成路径接进设备入口。

**关键发现**：全仓 `*.md` 里「统一指挥会话／派单／单入口」0 命中，这套法从来没被设计过，最接近的只是 `deliverables/tihu-mockups/README.md:53` 的痛点原文「多会话并行时不知道这句话注入了哪条」。

## 2. 目标 / 非目标

| 目标 | 非目标（明确不做） |
|---|---|
| 一个入口，一次说话，全程不用挑会话 | 不追求把任务执行正文塞进指挥会话（指挥会话永远不看正文） |
| 完成即播报 ＋ 屏上气泡，不点会话也能知道结果 | 不改「思考 ·」那一行（用户 2026-11-08 定案「目前挺好的」，本设计对它零改动） |
| 派单可预测：同一项目的话不会散到别的项目 | 不新开 WebSocket 端口，不加第二套密码，不动鉴权 |
| 任务级投影取代会话级投影 | 不删除既有能力：会话仍可手动打开（保留 `bind` 当逃生口） |
| 屏幕容量不变（320×240、正文 4 行、回复 7 行 × 20px） | 不做多设备同屏多路订阅（先单设备） |
| TTS 仍留在 `D:\dsh-assistant` 内（edge 主、Kokoro 兜底） | 不新增外部服务、不加新运行期依赖、不引入常驻 GPU 服务（96GB 机、strata 工作集 73GB 以上，须 CPU 友好） |

## 3. 备选方案比较（为什么选 B）

| 方案 | 做法 | 优点 | 否决理由 |
|---|---|---|---|
| A 单会话内联 | 所有任务都开在同一个会话里，一条会话跑全部 | 完全不用选会话，改动最小 | 上下文爆掉；一个任务卡住全队列；CU 会话占屏冲突；无法并行 |
| **B 统一指挥会话 ＋ 任务登记簿**（推荐） | 设备只绑指挥会话；它派单到别的会话；屏与播报按任务投影 | 入口唯一、可并行、通知可预测、与既有按项目建会话路径复用 | 需要新增登记簿与 `task.*` 投影（工作量最大，但收益正落在你的诉求上） |
| C 纯规则路由会话池 | 用别名/关键词规则把话直接投到既有会话 | 不用模型、延迟最低 | 规则表永远不全；新任务没有落点；歧义时仍要人挑会话 |

**B 落地后 C 并不消失**：C 的规则表就是 B 的「路由快路径」（第 6 节），慢路径才用模型。

## 4. 目标架构（图 1）

五层五部件，一条通道复用到底：

| 层 | 部件 | 职责 | 现有落点 |
|---|---|---|---|
| ① 设备 | 语音入口 ＋ 触屏 ＋ 喇叭 | 唯一入口，只说只听 | 不变 |

## 5. 任务登记簿（Task Ledger）

唯一事实源。会话是它的字段之一，不是它的父级。

| 字段 | 含义 | 来源 |
|---|---|---|
| `taskId` | 稳定短号（屏与播报都用它） | 登记簿生成 |
| 标题 | 一句话意图的规范化短语 | 转写清洗（`lane.ts:2382`） |
| `projectId` / `folder` | 派到哪个项目、落在哪个文件夹 | `projects.folders`（`client/index.tsx:169`）＋路由表 |
| `sessionId[]` | 承载执行的一条或多条会话 | 派单动作产生 |
| `preset` | standard 或 `computer-use` | `TIHU_COMPUTER_USE_PRESET`（`lane.ts:393`） |
| 状态 | 排队／派单／执行中／待决策／完成／已播报／归档 | 事件归一化 |
| 步数、用时、上下文占比 | 「跑到哪了」 | `progress.ts:applySessionEvent`（:428） |
| 结果摘要 | 完成时的一行话（不是正文） | 收工时蒸馏 |
| 播报标记 | 已播过没有、气泡有没有被点 | 通知总线 |
| 决策留痕 | 闸门快照／审计行 | `guard.ts:262-284`、`322-328` |

**「归档」只是任务的最后一态**：把任务从棋盘拿走、往 journal 追加一行摘要；**会话不删、文件夹不动**（与「删除会话」是两件事，删除仍是危险动作，需口头确认）。细节见 §8.5。

**事件归一化**：现有 `turn/start`、`tool/call`、`assistant/message`、`turn/end`（`session/event`）映射成 `task.started / task.step / task.awaiting / task.done / task.reported`。按任务映射去重，避免同一件事既进簿又上屏。

**投影改造对照**（要动的地方，按约束清单）：

| 现键 | 现位置 | 改成 |
|---|---|---|
| `pendingByDisplay`（会话 id → 气泡） | `lane.ts:474`、`1717-1749` | 任务 id → 气泡（完成即入队，点击只是「看一眼」，不切会话） |
| `homePinned`/`pinnedHomeFrames`（会话 id） | `lane.ts:490-496` | 主页钉＝任务棋盘钉（投影整体，不再按会话） |
| `runningSessions`（全局会话表） | `lane.ts:459`、`1945` | 登记簿的「执行中」集合（守门条件不变，口径换） |
| `replyHistory`/`lastAssistant`（按会话） | `lane.ts:476-498` | 按任务保留最近回复，回看＝回看任务 |
| `activeSessions` / `tihuTurnOf` 窗口 | `lane.ts:422`、`2427`、`2588-2596` | 窗口仍按会话（工具闸判据不动），但登记簿持有 `task→session` 映射供确认帧路由 |
| `home.projects[].sessionId` 点击即绑 | `lane.ts:1640-1645`、`3428-3453` | 主页行点击＝看这条任务，不再换屏绑定 |

## 6. 派单规则（指挥会话怎么决定）

**快路径（零模型，抢延迟）** — 命中即用：

1. 项目别名命中路由表（「基金那边」「青年那个」）→ 该项目的活跃任务会话；
2. 「上一条任务」接续（刚说过的同一件事）；
3. 同项目已有会话正在跑 → 追加进队（现有 `spawnParallelTask` 语式可复用：`lane.ts:2484-2535`）；
4. 只读问答类 ＋ 白名单（`tihuVoiceAutoEligible`，`lane.ts:227-232`）→ 直接答，不落任务。

**慢路径（模型，抢准确）** — 快路径不命中才走：读登记簿摘要 ＋ 热记忆 ＋ 项目路由表，让指挥会话选项目；歧义就「追问澄清一句」（四出口之一），屏上问一句等人答，不猜。

**派单四出口（图 2 ①）**：自己直接答 ／ 追加到已有任务 ／ 新派任务会话 ／ 追问澄清一句（＋ 汇报取消）。新派落点优先级沿用控制室既有规则：模板最新步骤目录 → `projects.folders[pid]` → 绑定会话 cwd（见 `latestStepDirOf`/`newSessionFolderOf` 交接），避免「新会话落错文件夹」。

**并发纪律**：每条会话一次只跑一个 turn，派单进队即排队；同项目多任务先入队再串行放行；跨项目并行。**指挥会话不执行任务正文**，只收摘要，避免上下文膨胀。

## 7. 项目文件夹判定：新派与追加到底落哪

一句话：**复杂任务跟项目卡片走，日常任务跟「个人助手」卡片走，追加不新建、不乱选。**

| 情形 | 怎么判 | 文件夹 | 会话 | 控制室卡片 |
|---|---|---|---|---|
| 复杂任务 · 控制室已有卡片 | 别名/记忆/最近任务命中该卡片 | `projects.folders[cardId]` | 该文件夹下**新开一条**会话 | 不动（已存在） |
| 复杂任务 · 控制室没有卡片 | 跨步骤、要产出文件、要跑很久 | 新卡片的 `folders[newId]`（你口述路径；没口述就按模板最新步骤目录） | 新卡片的默认会话 | **同步新建**，控制室立刻可见 |
| 日常简单任务 | 单步、问答、查一下、改一句 | 「个人助手」卡片（`wt-assistant`）的文件夹＝助手 home | 该文件夹下新开或复用空白会话 | 不新建、不占项目 |
| 追加到已有任务 | 同一件事接着说 | 不选（沿用原任务会话的 cwd） | 直接投进那条会话 | 不动 |
| 兜底 | 卡片没填文件夹 | 模板最新步骤目录 → 项目绑定会话 cwd → 助手 home | 同上 | — |

**三条落地要点**

1. **一个项目文件夹下允许 N 条会话**：卡片只记 `folders[id]`（文件夹）与 `bindings[id]`（默认会话）。派单新增会话**不覆盖绑定**，否则「派一次就把默认会话顶掉」，控制室点卡片会跳错。
2. **新建卡片必须双写，且只有一处真源**：`projects.layouts` 加 id、`projects.folders[id]` 写文件夹、`projects.order` 插最前；写入走既有 `/api/assistant/state`（`src/assistant-store.ts:14`，`persistProjects` 乐观并发，`createBoundSession` 已有同款写法 `client/index.tsx:4327-4347`），控制室 800ms push / 3s poll 自动刷新。**不做第二套卡片存储，鹈鹕不自己记项目。**
3. **日常任务的固定卡片**：直接用 `ASSISTANT_PROJECT_ID = 'wt-assistant'`（`src/client/assistant-card.ts:18`），它的 `folders[id]` 就是助手 home —— 和长按悬浮球的落点**完全一致**；因此「日常任务」不会在控制室多出一张卡，也不会把 `assistant` 文件夹搞乱。

**预设怎么选**：复杂任务默认 `standard`；要看屏/点鼠标的派 `computer-use`（`TIHU_COMPUTER_USE_PRESET`，`lane.ts:393`）；日常任务一律 `standard`。

**接现有代码**：`createCustomSession(projectId, …, folder)`（`client/index.tsx:1885-1923`）已经是「按项目建会话 ＋ 注入需求」的完整路径，派单直接调它；文件夹解析复用 `newSessionFolderOf(pid)` 的优先级（最新步骤目录 → `projects.folders` → 绑定会话 cwd）与 `ensureProjectWorkspace`（`client/index.tsx:480-561`）；**新增的只有**一个 `dispatchProjectCard(name, folder)`（建卡＋双写），其余全部复用。

## 8. 屏幕与播报改动（七屏 ＋ 一个空态，能沿用的沿用）

图 3 右侧是六张**真实渲染**的 320×240 屏（`deliverables/figs/screens/`，脚本 `screens.py`，可按 token 改完再渲）；下面这张表是清单：**七屏 ＋ 屏 1 的空态**。

> **屏 8 已取消（回答「会不会冲突」）**：原「空闲回棋盘」与「任务棋盘」是同一件事的两种脸——有任务就是棋盘、没任务就是空盘。合成一屏：**永远只有屏 1「任务棋盘」，没有任务时它就是空态**（中间一行「还没有任务 · 叫「你好，鹈鹕」说一句」，顶行三段计数归零）。所以不存在「有任务进屏 8 / 无任务进屏 1」的分流，棋盘只有一张。

**三件动效语言（八屏共用，别再加花样）**：波形 ＝ 在听／正在念；环 ＝ 已用时长（满圈 30 分钟，超过就绕满转琥珀＝跑久了；完成＝满环，排队＝空环）；文字 ＝ 精确时长（`12′20″`）。除此之外只用文字与色块，不加装饰动画。

**文案纪律**：只留对用户有用的信息。删掉「不用按住」「16 kHz 单声道」「松开就发送」这类解释性文字；同一屏不重复同一事实（标题说了「已派给 X」，正文就不再写一遍项目名）。

| 屏 | 触发 | 版式（沿用／新增） | 关键文案与元素 |
|---|---|---|---|
| 1 任务棋盘 | 待机／空闲／回主页 | **新**（沿用主页骨架：顶行 14px ＋ 5×34px 行 ＋ 底部翻页 28px，**去掉整条汇总横幅**） | 顶行＝时钟＋右端三段计数「●2 在跑　●1 等你　●1 排队」（左上连接点已删）；**每行＝状态胶囊（执行中／待决策／排队／完成）＋任务名＋副行「项目 · 第 N 步」＋右侧**时长环**（＝该任务已跑多久）；**待决策行右侧是琥珀问号徽标**（要人答，不显示时长） |

### 8.1 语音入口＝唤醒词「你好，鹈鹕」＋ 兜底

- **主路径**：叫「**你好，鹈鹕**」→ 屏上出「在听 · 已唤醒」→ 直接说 → **末字后静音 3 秒**判定说完（留出想措辞的时间；显式删掉了「再说「你好，鹈鹕」可打断播报」这行提示，能力保留、提示不上屏） → 自动转写并发送。全程不用碰屏。
- **为什么退出是 10 秒不是 3 秒**：3 秒会在「想怎么措辞」时就把人踢出去（真实场景里人常沉默 3–5 秒再开口）；10 秒既不会一直开着麦，也够人想一句。屏上写明「10 秒没说话就退出」，让人心里有数。
- **兜底**：长按屏幕任意位置 = 按住说话（保留旧路径，网络/唤醒词失效时仍能用）；点屏幕 = 打断朗读/退出聆听。
- **再叫一次可打断**：播报中叫「你好，鹈鹕」→ 停播 + 进聆听（念一半也能插话）。
- **误唤醒**：只做本地关键词判定（不上传音频），唤醒词与 VAD 都在设备侧；误唤醒不出「在听」、不产生任务。硬件侧要 AEC（播报时防自触发），这条写在既有播报方案 §5.6。
- **屏上只留三句**：`说完停 3 秒再发送`、`想清楚再说不着急`、`10 秒没说话就退出 · 长按也能说`。技术参数（16 kHz、单声道、本机转写）不上屏。

### 8.2 派单回执停多久，说「看任务」去哪

- 停 5 秒自动回棋盘；**任何交互都停住**（点屏、说话、长按），停住后回执留在页面栈里，按「主页」才退出——避免「派完单还占着屏」。5 秒够看清「落在哪个文件夹、排第几」，又不至于挡住你下一句。
- **说「看任务」/ 点「看任务」→ 屏 4 任务详情**（不是棋盘）：详情屏就是为这条链路设计的，实时状态＋统计＋上下文环＋`看会话/停止/回棋盘` 三个键。从棋盘点任意一行也进同一屏（同一版式，执行中／待决策／完成都复用它）。
- **说「撤单」**：任务还没起跑 → 直接撤；已起跑 → 先停再撤（要确认）；**说「停住」**：只停这张回执不动任务。
- 详情屏回退只有一条路：`回棋盘`（或说「回棋盘」），不会自己跳走，避免「看着看着被弹出去」。

### 8.3 任务棋盘怎么「去重、给文字」

- **顶行不再放横幅**：只留时钟＋连接点＋右端两项计数「●2 在跑　●1 等你」。原来是整条「2 条在跑 · 1 条等你 · 说一句就派单」的横幅，又长又挤，删掉。
- **一行只说三件事**：状态胶囊（文字，不只靠颜色）、任务名、副行「项目 · 第 N 步」＋右侧进度环。**不重复**：状态已说「完成」就不再写「已播报」；时间只在详情屏出现，棋盘行不塞时间。
- **同类合并**：同一项目连续多条只留最新一条（旧的折叠成「+2 条」提示行，点开看）。
- **显示顺序固定**：待决策 → 执行中 → 排队 → 完成（要人的永远在最上）。
- **颜色只做辅助**：胶囊本身带文字，色盲/强光下也能读。

### 8.4 「8 秒合并」到底是什么

不是屏上合并，是**语音合并**：完成事件先进两条队——屏气泡队（逐条显示，不合并）、语音播报队。语音队列每 8 秒取一次，把这段时间攒下的完成压成一句（「三件事完了：基金稿改完、磷石膏出图、设备联调通过」），只念一次；不足 8 秒只有一条就立刻念。目的：连着三个任务完成时不会「叮、叮、叮」念三遍。P0（要人）永远插队、不等窗口。

### 8.5 「归档」到底归档什么

**归档的是任务，不是会话、更不是文件夹**：从棋盘上移除这条任务、往 journal 追加**一行**摘要（`任务名 / 项目 / 会话 id / 用时 / 结果一行 / 谁拍的板`），会话与它的文件夹**原样保留**，随时能回控制室接着用。删除会话是另一件事（危险动作、必须口头确认，沿用今天的 `archive` 规则）。journal 是纯文本追加文件（`~/.dsh/tihu/journal.jsonl` 量级），供「上周那件事后来怎么样了」这类回忆查询。

### 8.6 「第 4 步」是什么意思（为什么没有 4/12）

- **步 ＝ 本次任务里第几次工具调用**（读文件、跑命令、写文件各算一步），由进度事件累计，**没有预先知道的总数**——模型开工时并不知道自己要走几步。
- 所以上一版写「4/12」是**编出来的分母**，会让人以为「还剩 8 步」，误导。**已删掉 4/12 和那一排 12 颗点**。
- 现在给三样真东西：① **第 N 步**（累计到哪了）；② **最近 8 步耗时微条**（节奏感，看得出卡没卡）；③ **上下文环**（唯一有分母的指标，41% 就是 41%）。加上原来的 `82 tok/s`、`12′20″`，与今天的执行页口径一致。
- 若某个任务真有计划步数（模板步骤／待办清单），只在详情屏加一行「清单 3/7」，**不写进任务本身的进度**，两者不混。

### 8.7 待决策 ＝ 托管没开 ＋ 电脑端同一个问题

- **只有「托管」没点亮时才可能出现待决策**：托管开着时，`plan-review` 自动选 `approve`、其余问题自动选**首选项**（无选项则回一段默认文本），人根本不会被问；托管一关，问题才落回人身上——屏上这时才弹「待决策」。
- **内容与电脑端一致**：同一个问题句（原样）、同一个上下文（路径／任务名）、同一组选项（顺序也一致），不另写一套措辞。
- **60 秒不答按默认选项走**：默认项 ＝ **首选项**（与托管开着时的自动选择完全同一条规则），屏上给默认项打 `默认` 标记。这样「托管开＝它替你选首选项」「托管关＝60 秒后仍按首选项」，两条路的结论一致，不会因为你在不在旁边而跑出两种结果。
- 回复方式：点选项、说「确认／留着」，或者干脆说一句自由文本（等价于手输回答）。

**播报优先级（固定，不商量）**：

| 档 | 内容 | 屏 | 语音 |
|---|---|---|---|
| P0 需要人 | 危险动作确认、待决策、歧义追问 | 立即上屏问句 | 打断当前朗读，立即播 |
| P1 完成 | 任务完成 ＋ 一行结果摘要 | 气泡入队 ＋ 任务行打勾 | 播（8 秒窗口内合并成一句总播） |
| P2 里程碑 | 阶段切换（如「第 3 段改完」） | 任务行摘要更新 | 可播（低优先队列） |
| P3 进度 | 步数、用时、上下文占比 | 屏上数字，不播 | 不播 |

合并规则：8 秒窗口内的多条 P1/P2 只播一次（「三件事完了：基金稿改完、青年卡在确认、设备联调通过」）；常用短句走缓存/预录（`~/.dsh/tihu/preroll/`，见既有播报方案 §3.4/§3.5）。朗读仍是单路串行、首段先播、端侧只播放不合成——沿用 2026-11-08 已定稿的 TTS 架构，本设计不新增引擎。

**「思考 ·」那一行：原样保留**，本设计不碰它（无中文词表、不滤英文／路径／命令／会话 id、不加测试断言）。

## 12. 风险清单与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 指挥会话上下文膨胀（把任务正文吸进来） | 派单变慢、成本变高、答非所问 | 只收摘要；正文永不进指挥会话；每轮注入≤ 项目路由表＋簿摘要 |
| CU 会话占屏冲突（屏幕被正在跑的任务占着） | 你在设备上说话却没有入口 | 入口永远在指挥会话；屏投影由登记簿决定，看的是任务帧而非会话帧 |
| 工具闸门判据换键（现按 sessionId 窗口） | 危险动作漏放行或错放行 | 窗口机制保持原样，登记簿持有 `task→session` 映射做确认路由 |
| 危险动作确认被吞（现 `confirm.ask` 按设备 sessionId 过滤） | 屏上没人回答，任务卡死 | P0 档优先级打断；确认句走指挥会话，回答回 `task.reply` |
| 自动跟随残留（旧代际机制与新架构并存） | 「屏幕自己跳」的老毛病复发 | P1 直接把 `autoFollow` 关掉只留 `bind` 逃生口 |

**与原设计的差异（都是执行时发现必须补的）**

1. **`deviceOnlineFor()` 必须认统一设备**：原来只认「绑着这条会话的设备」，而统一指挥下设备绑的是指挥会话 —— 不补这一条，危险动作会被判「设备不在线」直接拒绝，P0 待决策档等于没做。
2. **`confirm.ask` 不再发给统一设备**：它改走屏 5（`screen.frame` 的待决策帧）＋ `task.reply` 回程；老路径（设备直接绑着那条会话）仍发 `confirm.ask`，逃生口不变。
3. **建卡双写靠克隆既有布局**：卡片布局是客户端的 `LayoutSpec`（窗格/宽度/比例一堆字段），宿主手写一版会让控制室渲染出空壳；改成「克隆「个人助手」那张卡的布局，只换 id/标题」，保证结构合法。
4. **慢路径的最小实现**：快路径不命中时把话交给指挥会话的模型（带一段「你只派单、不动手」的铁律），由它调 `tihu dispatch`。这是设计里「慢路径」的最小可用形态，不引入新的路由服务。
5. **唤醒词在模拟页是显式开关**：真机走固件本地判定（不上传音频）；浏览器只能用 `SpeechRecognition` 做关键词聆听，所以它默认关闭、点一下才开，且提示「长按说话仍可用」。
6. **屏 6 用状态屏而不是 reply 模式**：设计表里屏 6 那 7 行正文是回答屏（04）的版式，但统一设备并不绑在那条任务会话上 —— 全篇朗读会和「一行播报」重复出声。现在的屏 6 = 「结果一行 ＋ 最多 3 行正文 ＋ 另有 N 条」，要看全文点「看任务」→ 详情 →「看会话」。要改成全篇朗读只动 `turn/end` 完成任务那一段。
7. **详情屏不自动回退**：详情屏不排空闲计时（设计 §8.2「回退只有一条路」），靠说「回棋盘」或点「回棋盘」/「棋盘」回来。
8. **日常任务每条各新开一条会话**：设计写的是「新开或复用空白会话」，这里只做「新开」——复用一条日常会话会让两条任务共用同一个 sessionId，而登记簿是 `task → session` 一对一映射，事件一进来就分不清是哪条任务（状态、步数、完成帧全会串）。会话多不多你在设备上看不到（屏上是棋盘），但要在会话列表里少见到，后续可以加一个「日常会话池 ＋ 任务内外两层映射」再做。
9. **快路径的判定顺序改了（这条是实测逼出来的）**：原设计把「日常小事」排在「片段命中项目卡」前面。连打 10 句验收时暴露：`青年基金第 4 段逻辑理顺` 只有 12 个字、没有产出型动词，会被判成日常小事扔进助手文件夹 —— 而它明明点了项目名。现在顺序是「整名命中 → 接着说 → **片段命中 ≥3 字** → 日常小事 → 弱命中（2 字）」，并把 `§13` 那条验收真的写成测试（10 句同项目，零错派）。
10. **播报预录真的落地了**：`~/.dsh/tihu/preroll/` 存裸 PCM（16 bit 单声道 24 kHz，正是 `tts.audio` 的格式），键＝音色＋文本；只缓存单句播报，条数 120 / 总字节 8 MB 双上限，超了删最老的；命中时**不合成**、直接把 PCM 发下去（测试用「预置缓存 → 断言合成 0 次」把这条钉住）。
