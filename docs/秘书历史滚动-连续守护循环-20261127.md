# 秘书页翻历史仍跳动（跳到上一批最早那条）——守护循环修复（2026-11-27 第三轮）

## 结论（先行）

`2cc358e` 只修掉了「跳回最新」，但补偿仍是**一次性**的：`planHistoryScrollRestore` 在 settle 后算一次、写一次 scrollTop，
之后**异步高度增长**（宿主 prepend 的 0 高壳被插件扫描渲染成折叠卡 0→40px、图片晚到、折叠展开）把锚点顶走，
再也没有第二次补偿。而**手机触摸/惯性滑动期间浏览器原生 scroll anchoring 被抑制**，这时插件补偿是唯一防线，
于是视图落到新加载批次顶部——用户看到的「跳到上一批最早那条」。

修法：加载**开始前**就起一个短命「守护循环」——`MutationObserver`（DOM 变化的同一任务尾部，早于下一帧 rAF，
所以同步生长当场纠偏、不画出跳帧）+ `rAF` 兜底，逐帧把锚点行的视口偏移钉回加载前的位置；
翻卡/重画期间锚点行短暂消失容忍 45 帧；安静 8 帧且已过 300ms 即收工，硬上限 1.2s；用户手势/页面隐藏/卸载立刻退出。

## 实证（真 Chromium + 真源码函数，原生 anchoring 开/关两种模式）

修复前（原生 anchoring 关闭 = 手机触摸滑动态）：

- 场景③ 宿主 prepend + 插件异步渲染新卡：端点偏移 **-20 → +1030（永久跳）** ← 用户症状
- 场景②/④ 翻卡跨过锚点 / 图片晚到：瞬时冲到 **+632** 再回 -20（先跳后回，不连续）

修复后（同一 harness，10 个场景全绿，逐帧轨迹漂移 0px）：

```
PASS 场景②（锚定开/关）翻卡跨过锚点 0px

PASS 场景⑤（锚定关）连续加载两次 0/0px

```
