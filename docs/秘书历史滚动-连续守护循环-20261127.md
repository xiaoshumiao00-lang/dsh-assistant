# 秘书页翻历史仍跳动（落到新加载批次最早那条）——连续守护循环（2026-11-27 第三轮）

> 用户原话：「历史消息加载完之后，会回跳到上一个历史消息的最早的那条消息，也会跳。我不希望跳，
> 我希望连续，一定要连续。」
> 上一轮 `2cc358e` 只修掉了「跳回最新」，本轮把「任何方向都不许跳」收口。

## 一句话结论

**根因**：`2cc358e` 的补偿是**一次性**的（settle 后按锚点算一次、写一次 scrollTop）。写完以后仍有
**锚点上方的异步高度增长**：宿主 prepend 的「0 高壳」被插件扫描（120ms 去抖）渲染成折叠卡（0→约 35px）、
图片晚到、折叠卡展开。而这些增长发生时，**手机触摸/惯性滑动期间浏览器原生 scroll anchoring 被抑制**，
插件那唯一一次补偿早过去了，于是锚点被整批高度顶下去——视口正好落到**新加载批次顶部**（30 张 × 35px ≈ 1050px）。

**修法**：加载**开始前**就起一个短命「守护循环」——`MutationObserver`（DOM 变化同一任务尾部，早于下一帧
rAF，同步生长当场纠偏、不画出跳帧）+ `rAF` 兜底，逐帧把锚点行的视口偏移钉回加载前的位置；一旦检测到
`scrollTop` 被**外部**改过（用户自己滑 / 原生锚定已补偿），就把期望重设成当前值、**一个像素都不重复补**。
锚点情形下一次性 plan 不再写（它分不清「用户惯性滑动」与「内容增长」，写了会把人拽回）。翻卡/重画期间
锚点行短暂消失容忍 45 帧；安静 8 帧且已过 300ms 收工，硬上限 1.2s；页面隐藏/卸载立刻退出。

## 根因证据（排查方向逐条）

1. **锚点挑选与 offset 基准没有选错**：`pickHistoryAnchorKey` 在加载**前**取「文档顺序第一个底部越过
   滚动口顶部的非零卡行」，`captureHistoryScrollSnapshot` 的偏移基准是 `scroller.getBoundingClientRect().top`
   （相对滚动口顶），恢复公式 `after.scrollTop + (after.offset − before.offset)` 与该基准自洽。
   真 Chromium harness（原生锚定开）里「翻卡增长在锚点下方」场景锚点 0px 不动（场景①），说明口径本身没错；
   只有「增长在锚点上方 + 原生锚定被抑制」才跳。
2. **异步高度变化没有二次补偿（主因）**：场景③（宿主 prepend 30 行 0 高壳 + 插件 120ms 后补卡）
   原生锚定关闭时端点偏移 **−20 → +1030px（永久跳）**，正好等于 30×35px 的整批高度——视图落到新批次顶部；
   场景②/④ 瞬时冲到 **+632px** 再回 −20（先跳后回）。修复前原始输出见 `.tmp/continuity-RED-before-fix.log`。
3. **宿主自己那路 prepend 补偿不背锅，但它救不了晚到的卡片高度**：宿主确实有独立补偿
   （从 asar 提取核对：`dsh-client-ui-chat/src/client/chat/use-chat-viewport.ts:1036-1054`
   `beginHistoryPrepend/finishHistoryPrepend`、`use-chat-scroll.ts:164-169` 的 `preservePosition`），
   且它是「重新量当前行再钉回」的幂等口径，不会和插件重复补。问题是它只在 **prepend 提交那一帧**
   补偿，而那时 prepend 进来的行还是 **0 高壳**（插件还没渲染卡）；真正的高度在 120ms 后插件扫描补卡时才出现——
   宿主早补偿完了，插件的一次性补偿也早完了，这份「晚到的高度」没人补。
4. **锚点行不可见时的 fallback 不会跳到批次顶部**：场景⑥（锚点行被宿主重画抹掉）插件 `keep` 一个像素都不写
   （scrollTop 200→200），不跳到任何一行。这条不是本轮病根，但一并纳入验收，防回归。
5. **用户惯性滑动不能被钉死（本轮新发现、必须一起修）**：一次性 plan 的「无手势」分支也分不清
   「用户惯性滑动」和「内容增长」——touchend 后的惯性滑动不再派发手势事件，plan 会按旧偏移把 scrollTop
   写回去，把人拽回加载前的位置；而「绝对钉偏移」的守护若不在外部滚动时重设期望，会把用户自己的
   惯性滑动整个钉死（修复前的守护实测：用户上滚 160px，scrollTop 400→400、锚点 −10→−10，滑动卡住）。

## 已知残余边界（如实记录）

- 守护硬上限 1.2s：极慢图片如果晚于 1.2s 才撑高，仍可能有一次小跳（原生锚定开时由浏览器兜住；
  手动划动/触摸后守护会重设期望，不会和用户对抗）。
- 「贴底跟随最新」沿用一次性 plan（钉地板），不在守护范围内；进入秘书页默认钉底、不自动回填的行为不变。
