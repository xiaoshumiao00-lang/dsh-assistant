# 作者本地脚本（不进仓库、不随包分发）

P0-6（2026-11-05）：`scripts/apply-desktop-host-auth-cookie-fix.ps1` 已从仓库移到 `.author-local/`
（该目录在 `.gitignore` 里，`package.json` 的 `files` 也不包含它）。

## 它原来做什么

给**作者这一台机器**上的 DSH Desktop 打一个宿主补丁：

- 改写的目标写死为 `D:\DSH Desktop\resources\app.asar`；
- 期望哈希写死为作者某次构建的 `58A3709A…71B74`（换个 DSH 版本就对不上）；
- 会等 DSH 退出 → 用 `.patched-host-auth-cookies-20261028` 覆盖 `app.asar` → 校验 SHA-256 → 写日志到 `D:\dsh-assistant\scripts\app-asar-patch.log`。

## 为什么不能给别人

1. 路径、哈希、日志位置全是作者本机的，别人跑只会 `exit 4/6/7`；
2. 它**改写宿主 `app.asar`**（monkey patch），不是插件能力；随包分发等于让第三方用户去动 DSH 安装目录，风险远大于收益；
3. 该补丁对应的宿主问题（浏览器访问的 auth cookie）已由上游版本处理，新装环境不需要它。

## 作者本机还要用怎么办

脚本仍在 `.author-local/apply-desktop-host-auth-cookie-fix.ps1`（内容与移走前一致）。用法：

```powershell
pwsh -File .author-local\apply-desktop-host-auth-cookie-fix.ps1
```

只在这台机器的 DSH 版本与脚本里记录的哈希一致时才有意义；换版本前先把 `-ExpectedHash` 改成新构建的值。

## 给别人装的时候

不需要、也不要执行这个脚本。第三方用户只需要：

```powershell
node build.mjs        # 或在拿到 tgz 后 dsh plugin add
node scripts\install-assistant.mjs desktop
```

然后到「设置 → 个人助手 → 本机配置」填自己的路径 / 词表 / 更新源（见 README「给其他人装」一节）。
