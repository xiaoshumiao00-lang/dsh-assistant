# 安卓后台保活 · 切回秒恢复 · 后台任务完成播报（2026-11-27）

需求原话：「打开 APK 正常状态后切到后台（比如看微信、发消息），过一会再打开个人助手，
它又要重新连接、又要等几秒。我希望从后台切回来还是正常的已连接状态，不要重连白等。
最好常驻后台时都保持在线，这样后台突然有任务完成，语音播报也能及时收到，而不是等我
回到界面、重连之后才收到。」

交付版本：**个人助手-通用版 1.4.8（versionCode 35）**，必须重装 APK（改了 Java/Manifest）。

## 1. 现状取证（改动前行号）

### 1.1 WebView 生命周期（MainActivity.java，改动前）

- `onPause()` L1237–1245：调了 `web.onPause()`——它会暂停 WebView 的媒体与部分处理；
  后台恰恰要靠 JS 定时器 / WebSocket / 音频继续跑，这是「切后台就断」的人为因素之一。
- `onResume()` L1248–1252：只 `web.onResume()` + 状态栏，不重载（这点本来就对）。
- `onDestroy()` L1255–1269：`web.destroy()`。Activity 是 `singleTask`
  （AndroidManifest.xml L35）+ 吞掉全部 configChanges（L32），按 Home 键不会走到
  onDestroy，WebView 本身能活——**真正杀连接的是进程被厂商省电冻结/杀掉**。
- `onRenderProcessGone` L382–385 → `recoverWebView()` L249–269：渲染进程死了会重建
  WebView 并回首页（已有，等同刷新一次）。
- Manifest 改动前权限只有 INTERNET / ACCESS_NETWORK_STATE / RECORD_AUDIO /
  MODIFY_AUDIO_SETTINGS / CAMERA / WRITE_EXTERNAL_STORAGE(≤28) /
  REQUEST_INSTALL_PACKAGES——**没有任何保活/通知相关权限，没有服务声明**。
- minSdk 24 / targetSdk 34（android/build.ps1 L46–47）：targetSdk 34 要求前台服务
  必须声明类型（manifest + 运行时三参 startForeground），Android 13+ 通知是运行时权限。

### 1.2 WebView 侧连接在哪、隐藏时会不会主动断

- 页面就是电脑上的 DSH web（经 pocket 代理透传），实时通道是 DSH 自己的
  `dsh-client-connection` 浏览器包向 `/api/events.mux` 建的 WebSocket
  （代理透传见 src/pocket-host/proxy.mjs L1294 注释）。
- 本仓库页面侧（src/client/pocket）**没有任何 WebSocket/reconnect 逻辑**，也没有
  pagehide/visibilitychange 时主动断开或重初始化连接的行为：
  - orb/diag.ts L629–649 只在 pagehide/visibilitychange 发诊断信标；
  - mobile/mobile-apply.tsx L722–733 只在恢复可见时补打模型设置提示；
  - turn-guard.ts L173、tuoguan.tsx L527、assistant.tsx L163、split.tsx L2711
    都是「可见时刷新数据」，不动连接。
- 唯一客户端 WS 是 split.tsx L3845 的终端窗（/api/worktable/term），与主连接无关。
- **DSH 连接层的退避参数**（从 D:\deepseek-harness\resources\app.asar 内
  dsh-client-connection/lib/client.browser.js 只读取证）：
  `ConnectionRecoveryConfigSchema` 默认 `backoffBaseMs=500, backoffFactor=2,
  backoffMaxMs=10000`，状态机三态 `connecting/disconnected/connected`，并暴露
  `reconnect()`（退避清零、立即重试）与 `state.getSnapshot()/subscribe()`。
  也就是说「重连白等」= 回前台时连接层正好睡在 0.5s×2ⁿ 的长退避上。
- 代理已有协议层心跳（proxy.mjs L771–834 `attachWebSocketHeartbeat`：30s 向浏览器侧
  发 WS Ping，连续 2 个静默周期判死主动断开让客户端重连）——**30s ping 心跳已存在，
  本次不动**。

### 1.3 前台服务 / 通知 / TTS 桥现状

- 改动前 android/ 全目录 grep `JavascriptInterface|addJavascriptInterface` = **0 匹配**
  （docs/秘书回复卡图片-原生下载与看图-20261127.md L38–40 也记过这个事实）；
  没有 NotificationManager、没有原生 TextToSpeech、没有前台服务。
- 现有 TTS：秘书回复卡自动朗读走宿主 `POST /api/assistant/tts`（微软 edge-tts → MP3 →
  WebAudio 排播，src/client/pocket/orb/secretary-speech.ts）；自动朗读唯一入口是
  `requestAutoReadOnce()`（SecretaryReplyCard.tsx L586 调用，secretary-speech.ts
  L150 定义）。**后台 WebView 的 AudioContext 被挂起、定时器被节流，这条 JS 链路在
  后台播不出声**——所以后台分支必须落到原生。

## 2. 方案总览

- **A 保活（常驻在线）**：新增前台服务 `KeepAliveService`（dataSync 类型），常驻最低
  优先级通知「个人助手常驻连接中」；START_STICKY + onTaskRemoved 3s 闹钟拉回 +
  约 9 分钟 `setAndAllowWhileIdle` Doze 节拍（每拍续 10 分钟部分唤醒锁）；
  Android 12+ 后台起服务被 `ForegroundServiceStartNotAllowedException` 拦住时吞掉
  （回前台 onResume 补拉）。进程优先级钉住，厂商清理/冻结才不会动 WebView 的 WS。
- **B 切后台不丢连接 + 秒恢复**：
  - 原生：`onPause` 不再暂停 WebView（JS/WS/媒体继续跑）；`onResume` 只做页面探活
    （evaluateJavascript 递一句 JS，5 秒无应答 = 渲染卡死才 recoverWebView），
    **绝不无条件 reload**；
  - 页面：新增 `foreground-nudge.ts`——`visibilitychange` 变可见时读
    `connection.state.getSnapshot()`，不是 `connected` 立刻 `connection.reconnect()`
    （DSH 连接层自带：退避清零立即重试），仍没连上按 **2s→4s→8s→15s→30s** 阶梯补刀，
    重新隐藏即停。心跳沿用代理 30s 协议层 ping（未改）。
- **C 后台收任务完成 + 播报**：自动朗读唯一入口 `requestAutoReadOnce` 新增后台分支——
  页面不可见（`document.hidden`）**或**原生标记后台（`isAppInBackground()`）且桥在时，
  改走 `DshAssistantNative.speakNative`（原生 TextToSpeech，中文，长文切块）+
  `notifyTaskDone`（渠道 dsh_task_done、IMPORTANCE_HIGH、点击回 MainActivity）；
  「已播报」双保险去重：JS 侧 `__dshNativeSpokenKeys`（globalThis Set）+ 原生
  `spokenKeys`（10 分钟窗口），回前台不会因卡片重挂载重读。前台/无桥环境行为不变。
- **D 省电策略**：设置页新增「后台保活」区块——前台服务开关（默认开）+
  「电池优化白名单」入口（显示 已加入/去加入，点击才跳系统授权页，绝不自动弹）；
  Android 13+ 启动时申请一次 POST_NOTIFICATIONS。

不破坏现有功能：附件下载链路（DownloadListener/startDownload）一行未动；卡片、
语音输入、桌面快捷方式均未改；onDestroy 仍正常销毁 WebView。

## 6. 真机验证步骤

1. 装 1.4.8 → 首次打开允许「通知权限」（Android 13+ 弹一次）。
2. 进设置页（长按返回键）确认「后台常驻保活：已开启」；小米/华为等机型点
   「电池优化白名单：去加入」跳系统页允许（状态变「已加入」）。
3. 正常连上助手后切到微信发几条消息，**等 2 分钟**再切回：
   预期**秒恢复已连接**（不出现「重新连接」转圈）；通知栏有一条
   「个人助手常驻连接中」常驻通知（最低优先级，不响不震）。
4. 切后台后让电脑端跑完一个任务（秘书会话出新回复）：
   预期**几秒内**收到高优先级通知「个人秘书 · 任务完成」，并且**手机直接语音播报**
   该回复（原生 TTS）；点通知回到会话，同一条**不会**再重读一遍。
5. 锁屏 10 分钟以上（浅 Doze）：任务完成仍应收到通知与播报（9 分钟兜底节拍 +
   唤醒锁在工作）；深度 Doze（数小时静置）属平台限制，回到前台时页面侧
   「可见即重连」会在 1 秒内把连接拍醒。
6. 回归检查：秘书回复卡附件（docx/apk/图片）点击仍走系统下载并分流打开；
   语音输入（麦克风）正常；卡片渲染无变化。

## 7. 已知边界

- 厂商「自启动管理/后台清理」白名单（小米神隐模式、华为应用启动管理等）无法程序化
  引导，电池优化白名单已覆盖最主要一项；个别 ROM 仍需手动允许自启动。
- 原生 TTS 用系统引擎：没装中文语音数据的设备会退回默认语言或只发通知
  （通知标题会注明「语音不可用」）。
- 原生桥 `DshAssistantNative` 只在安卓外壳存在；桌面/浏览器自动落回现有
  微软 TTS + WebAudio 路径，行为零变化。
