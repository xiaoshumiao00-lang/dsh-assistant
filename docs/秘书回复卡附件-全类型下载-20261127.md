# 秘书回复卡附件：所有类型统一下载链路（2026-11-27）

需求原话：「不只是图片，所有的附件（包括 apk 等）都通过下载实现。」——秘书回复卡里的**任何附件**
（apk、docx、xlsx、pdf、zip、音频、图片…）点击后都必须走系统 `DownloadManager` 下载，
**绝不能在同页打开或刷新掉 APK**；下载完成后按类型交给系统应用打开。

结论：JS 侧图片/文件收敛成同一个 `openAttach`（安卓 UA 一律 `download=1`，桌面保持
`window.open`）；服务端 `download=1` 对全类型强制 `attachment` 并补正 apk MIME；安卓端
下载完成按 MIME 四路分流（看图 / 安装 / 文档·音频 / 仅通知）。测试 88 个脚本 86 过 2 红
（两个都是已知红，无新红），APK 1.4.7(34) 已出并签验通过。

## 2. 为什么之前文件与图片是两条路

2026-11-26 附件需求落地时只有**一条**路径：`window.open('/api/worktable/file?path=…')`，
由服务端 content-disposition 决定命运——图片/pdf/文本回 `inline`（标签页直接看），
docx/zip 等回 `attachment`（浏览器下载）。桌面浏览器下这条单路径工作良好。

APK 的 WebView `setSupportMultipleWindows(false)`，`window.open` 退化成**同页导航**：
- `attachment` 类型（docx/zip…）WebView 渲染不了 → 回调 `DownloadListener` → 系统下载，恰好能工作；
- `inline` 类型（图片，以及 pdf/txt/mp3！）被 WebView 在当前页直接渲染 → 卡片页被整个刷掉
 （用户看到「APK 重新刷新、重新进」）。

85d4a13 只给**图片**打了补丁（图片点击加 `download=1`），文件条仍 `window.open` 碰运气——
遇到 pdf/txt/mp3 这类 inline 附件照样刷页面。本轮把判定收敛到 `openAttach`：安卓 UA 下
**任何附件**一律 `download=1` 强制 attachment，同页导航这条路被彻底堵死；桌面保持
`window.open` 新标签页不变。

## 3. 安卓端 MIME 分流表（下载完成后）

| 类型 | 判定依据 | 动作 | 拉起失败兜底 |
|---|---|---|---|
| 图片 png/jpg/jpeg/gif/webp/bmp/svg | `isImageDownload`：下载器 MIME `image/` → 扩展名 | `ACTION_VIEW` + content Uri + `image/*` → 系统看图 | toast「没找到能看图的应用，点通知栏那条打开」 |
| apk | `downloadMime`：服务端 MIME / 扩展名小表 → `application/vnd.android.package-archive` | `ACTION_VIEW` + content Uri + 钉死 APK MIME → 系统安装界面（清单已加 `REQUEST_INSTALL_PACKAGES`） | toast「安装界面拉不起来，请在文件管理器里点它安装」 |
| pdf | `application/pdf` | `ACTION_VIEW` → 阅读器/WPS | toast「没找到能打开它的应用，请在文件管理器中打开」 |
| doc/docx/xls/xlsx/ppt/pptx | ms-office / OOXML MIME | 同上 | 同上 |
| txt/log/md/csv 等文本 | `text/*` | 同上 | 同上 |
| 音频 mp3/m4a/wav/ogg… | `audio/*` | 同上（系统播放器） | 同上 |
| zip 及其他未知二进制 | 不在以上名单 | **不拉起**，保持通知 + toast「点通知栏那条可以直接打开」 | —（不抛异常） |

所有拉起都走 `DownloadManager.getUriForDownloadedFile` 的 content:// Uri +
`FLAG_GRANT_READ_URI_PERMISSION`；禁 file://（Android 7+ 会 `FileUriExposedException`）。

## 6. 是否必须重装 APK

**必须重装。** MIME 分流、`openDownloadedFile`、`REQUEST_INSTALL_PACKAGES` 全在 Java 侧，
旧 APK（≤1.4.6）只有「图片看图、其他 toast」。JS/服务端改动随宿主生效即可，但安卓端分流
只有 1.4.7(34) 才有。同一 keystore 直接覆盖安装，设置与下载记录保留。
