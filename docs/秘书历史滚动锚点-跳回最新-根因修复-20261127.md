# 秘书会话「查看历史跳回最新」根因修复（2026-11-27）

> 用户手机实测原话：「个人秘书在查看历史消息时还是不好用，向下滑，滑到正在下载，过了一会刷出来后，
> 又跳回到最新消息了，不连续，历史消息应该接着加载出来啊，不应该跳到最新的位置，应该连续。」

## 一句话结论

**根因**：dsh-assistant 秘书卡片分页在 `expandOlder` 后用「scrollHeight 差值整体补偿」恢复滚动位置，
但折叠行→完整卡的翻转发生在**窗口边界（阅读位置下方）**，整体补偿把视图往下拽几千 px（一拽 24 屏），
落点距底 < 25px 时宿主 follow 采样还会把 `followingTail` 重新置真、之后钉死在最新。
**修法**：改成「第一个可见卡行」锚点补偿——无手势时只复原锚点屏幕偏移（宿主已补偿的 prepend 不重复补）、
有手势时只补锚点内容坐标位移（用户自己的滚动不拽回）；只有加载前后都贴底（距底 < 80px）才跟随最新；
「正在加载」提示的插删被锚点偏移自然盖住。

## 根因（哪一路把 scrollTop 改回底部）

1. **主因（dsh-assistant 旧补偿公式方向性错误）**：`SecretaryUserCard.tsx` 原 498-499 行
   `el.scrollTop = beforeTop + (afterScrollHeight - beforeScrollHeight)` 假设「加载期间所有高度增长都在
   阅读位置上方」。实际上列表几何是「折叠行区（更旧）→ 完整卡窗口（最近 30 张）」，
   `expandOlder` 把窗口边界处的 30 张折叠行（40px）翻成完整卡（~600px）——增长发生在**边界处**，
   而用户上滚到 240px 触发线时读的是**顶部折叠行区**，增长整体在阅读位置**下方**（离线模型实测：
   90 折叠 + 30 完整的列表、scrollTop=200 时，一次 expandOlder 增长 16800px 全部在锚点下方）。
   旧公式把 16800px 全加到 scrollTop（200→17000），锚点行屏幕偏移 0→-16800——视图被拽向最新 24 屏。
2. **放大器（宿主 follow 采纳）**：短列表（整页 ≈ 一屏）时旧公式落点距底 < 25px，宿主
   `use-scroll-follow.sample()` 把 `followingTail` 置真，之后每次内容增长/resize 都
   `followTail()→scrollToBottom`——用户被钉在最新消息，「又跳回到最新消息了」。
3. **「正在下载」提示**：宿主历史控件（`data-chat-history`）在加载时变高/状态切换，位于锚点上方；
   旧公式对它既没有单独处理，又与宿主 prepend 补偿重复计算。

## 修法（锚点口径，三条 + 手势感知）

新纯函数 `planHistoryScrollRestore(before, after, { userGestured })`
（`src/client/pocket/orb/secretary-cards.ts`，离线单测直接喂数值模型）：

1. **跟随最新闸门**：加载前距底 < `HISTORY_FOLLOW_BOTTOM_PX`(80) 且加载后仍贴底（允许地板被 prepend
   推高等量下移）且**内容真的长了**（floorGrowth > 0.5，失败/空页不把贴底用户再往地板上拽）
   → 钉到 after 的底；否则绝不主动跟随最新。
2. **锚点补偿**：加载前记下「第一个可见卡行」（`pickHistoryAnchorKey`：文档顺序第一个底部越过
   滚动口顶部的非零卡行，完整卡/折叠行都带 `data-dsh-scard-key`，翻卡后 key 不变还能找回）；
   加载后按 key 重测（`captureHistoryScrollSnapshot`）：
   - **无用户手势** → 屏幕偏移复原：`scrollTop = after.scrollTop + (after.anchorOffset - before.anchorOffset)`。
     增长在锚点下方 → 偏移不变 → **keep，一个像素都不写**；宿主自己已补偿的 prepend（偏移被宿主保持）
     → 同样 keep，**不重复补偿**；没人补偿的上方增长（翻卡跨锚点、提示控件变高、提示行插删）→ 偏移
     变多少补多少；
   - **有用户手势**（await 期间 touchstart/touchmove/wheel/pointerdown/keydown 任一）→ 内容坐标位移：
     `scrollTop = after.scrollTop + Δ(anchorOffset + scrollTop)`，用户自己的滚动分量天然抵消，
     **不把用户拽回加载前的位置**。
3. **锚点丢失**（宿主整棵重画）→ keep，一个像素都不写（瞎补比不补更糟）。
   「正在下载/正在加载」提示的插入/移除/变高都在锚点上方，被第 ② 条的偏移差自然盖住。

## 手机 WebView 静态走查（Android WebView / Chromium，滚动宿主 `[data-conversation-scroll]`）

1. **首次进入**：宿主 `reading.restore()` 无保存位置 → `followTail` 钉底；dsh `ensureWindow` 只取最近
   30 张（更早压折叠行）；scrollTop 在底部 ≫ 240 触发线 → `shouldExpandOnScroll=false` → 不取更早。
   结论：进入钉底、不自动回填，无回归。✓
2. **触底加载**：上滚至 scrollTop ≤ 240 → expandOlder；锚点 = 第一个可见卡行；30 张折叠行在**边界**
   （锚点下方）翻完整卡 → 无手势 ΔA=0 → keep 一像素不写；有手势 ΔC=0 → keep。视图停在正在读的行，
   「接着加载出来、连续」。✓
3. **连续触底多次**：窗口 30→60→90→120，每轮重新挑锚点、逐轮补偿正确（单测场景③漂移 0.0px）；
   到 120 上限 → capped → 触发判据被挡 → 不再取数；「更早的内容请到轨迹/搜索里看」提示行插在渲染区
   最前（锚点上方），落在某轮 await 内则被 ΔA 精确补偿。✓
4. **用户中途上滚（加载在飞）**：await 期间任何 touch/wheel/pointer/key 手势 → 内容坐标位移公式，
   用户滚动分量抵消，只补锚点上方净增长；无增长时 keep，**不拽回**（单测场景⑤a/⑤b）。✓
5. **加载失败重试**：fetch 失败 → pager resolve `{ok:false}`（不 reject）→ DOM 零变化 → keep 不跳；
   `expandingRef` 与手势监听都复位，下次触底可重试；宿主控件转「重新加载」的高度变化在 await 内
   被 ΔA 盖住；锚点行被整棵重画抹掉（极端）→ keep 不瞎补。✓
6. **「正在下载/正在加载」提示插删**：控件在锚点上方，插入/移除/变高 → 无手势按 ΔA 精确补偿、
   锚点不动；宿主已自己补偿的（finishHistoryPrepend / overflow-anchor）ΔA=0 → 不重复补偿。✓

**已知残余边界（如实记录）**：有手势 + 宿主 prepend 同帧重叠时，内容坐标公式会把宿主已补偿的
G_host（≈一屏内折叠行高度）再补一次；无手势时该场景正确（场景②c）。旧公式在同场景把下方翻卡增长
也全补（错得更多）。该重叠需要「用户 fling 穿过宿主 2 倍视口阈值与 dsh 240px 阈值且两个 fetch 同帧在飞」，
手机上为低概率瞬时态，且随后续滚动锚点会重新收敛。
