## 1. 第 1 点：坐标模式默认像素

### 1.1 改前原文（`src/coordinate-mode.ts:41-44`）

```ts
/** 与 dsh-orb 相同的缺省：Windows 用千分比，其它平台用像素。 */
function defaultMillifraction(): boolean {
  return process.platform === 'win32'
}
```

### 1.2 改后（同文件 `41-44` 行，行号未变）

```ts
/** 缺省关掉千分比：含 Windows 在内全部平台走截图原始像素（2026-11-25 起）。 */
```

`process.platform` 这个判据被整条去掉：win32 也不再默认千分比。依赖它的是 `readMillifraction()`（`src/coordinate-mode.ts:46-52`，没有配置文件时回落到这里）和设置页 GET 里的 `defaultEnabled`（`src/coordinate-mode.ts:139`、`154`）。

### 1.4 为什么是 per-session，以及为什么旧会话不变

| 环节 | 位置 | 行为 |
| --- | --- | --- |
| 服务读文件 | `lib/index.js:3734` `let enabled = readMillifraction(file)`（源码 `src/coordinate-mode.ts:89`） | **只在 register 时读一次**，写进闭包；`currentMode()` 每次返回闭包值（`lib/index.js:3735`，源码 `src/coordinate-mode.ts:91`） |
| CU 会话创建时盖章 | `lib/computer-use.js:3036` `ctx.on("agent/created", …)` → `3017 stampCoordinateMode` | 新 CU 会话创建那一刻才问 `service.currentMode()`（3019-3021），然后 `sessionModeCache.set(session, mode)`（3022）并写进该会话日志（3025 / 3028，`computer-use/coordinate-mode` 事件） |
| 读回只认本会话 | `lib/computer-use.js:2912 coordinateModeOf` = 日志里的记录 ?? 本会话的 process-local cache ?? `"millifraction"` | 每个会话按自己日志里那条记录走，**不跟全局设置**；所以切默认只影响**之后新建**的 CU 会话，已经在跑的会话坐标语义不变 |
| 已有记录/历史恢复不覆盖 | `lib/computer-use.js:3018` `if (hasCoordinateModeEvent(session) || hasEndSeed(session)) return;` | 会话里已有记录、或 resume 一个带 `session/end-seed` 的日志，都不重新盖章 |

这里同时是「必须重启」的证据：闭包里的 `enabled` 在 register 之后没有任何 file watcher / 定时重读，直接改磁盘上的 JSON 不会改变运行中进程里的值。**唯一的免重启路径**是设置页那个开关走 `POST /api/assistant/coordinate-mode`（`src/coordinate-mode.ts:143-156`，内存同步更新），但那是 UI 操作，本次没做（用户只要求改文件）。
