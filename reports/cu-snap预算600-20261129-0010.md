## ④ 472–485 ms 的补扫，在 600 ms 预算下是否落预算内？

### 结论

**落预算内**——但仅在「默认值路径」成立，且余量取决于机器当次负载（实测一次整条 click 用时 566 ms，只剩 34 ms 余量）。

- 默认值路径（`DSH_CU_SNAP_BUDGET_MS` 未设，**当前环境就是这种情况**）：预算 = 600 ms，472–485 ms 的补扫能跑完、建表、继续吸附判定。
- 被覆盖路径（环境变量设了值）：预算**等于**该值（不是「取小」），设成 < 472 就不落；设在 472–485 之间则取决于当次实测耗时。

### 预算的实际生效方式（代码证据，行号按改后文件）

| 行号 | 代码 | 含义 |
|---|---|---|
| 1238 | `const SNAP_BUDGET_ENV = "DSH_CU_SNAP_BUDGET_MS";` | 环境变量名 |
| 1239 | `const SNAP_DEFAULT_BUDGET_MS = 600;` | **本次改动**：默认封顶 600 ms |
| 1266–1269 | `function snapBudgetOf(env) { const raw = Number(env?.[SNAP_BUDGET_ENV]); return Number.isFinite(raw) && raw > 0 ? raw : SNAP_DEFAULT_BUDGET_MS; }` | **环境变量是「整体覆盖」，不是 min(默认, env) 取小**：只要 env 是正有限数就直接用它，否则用 600 |
| 1556 | `const budget = snapBudgetOf(process.env);` | 每次点击取一次预算 |
| 1586 | `deadline: started + budget` | 绝对截止时刻 = 点击开始 + 预算 |
| 1454–1461 | `const remaining = Math.max(1, input.deadline - Date.now()); if (remaining < 20) … timeout` | 剩余预算即子进程允许运行时间 |
| 1490–1499 | `setTimeout(() => { child.kill(); finish({ timeout: true, warn: "scan killed at …ms" }) }, remaining)` | 到点 kill，判超时 |
| 1520–1527 | `if (Date.now() > input.deadline) … "scan finished over budget"` | 子进程退出后仍过点 → 判超时放行 |
