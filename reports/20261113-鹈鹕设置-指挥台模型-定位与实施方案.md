## 2. 「指挥台」会话的模型目前怎么决定

### 2.1 唯一可用的宿主通路：`sessionController.selectModel`

- 入口：`D:\deepseek-harness\packages\api\session-controller\src\index.ts:311`（`@Remote('selectModel')`）
- 实现：`packages/api/session-controller/src/commands.ts:157-188`
  - `:176` `this.agents.selectForNextRequest(agent, selected)`
  - `:177-181` **顺手** `ctx.agentDefaultModel.saveSelection(selected)`（会改全局默认模型！）
- 落盘：`packages/api/session-controller/src/agent.ts:339-342`
  ```ts
  selectForNextRequest(agent, selection) {
    agent.session.append('model/selection', selection)   // 会话内持久事件
    this.selectionFor(agent).current = selection
  }
  ```
  ⇒ **per-session 模型是会话日志里的 `model/selection` 事件，天然持久、重启还在**。GUI 底部的模型名就是这个选择的显示。
- 建会话时带模型：**没有**。`SessionCreateRequest` 只有 `workspaceId/cwd/sessionId/agentPreset`（`model-select.ts:1-27` 顶部注释已论证），所以必须"建完再选"。

### 2.2 鹈鹕侧接线（现状）

| 位置 | 作用 |
|---|---|
| `src/tihu/model-select.ts:79-134` | `selectModelKeepingDefault()`：快照全局默认 → `selectModel` → **把全局默认写回**；进程级串行队列；永不抛 |
| `src/tihu/model-select.ts:137-173` | `resolveTihuModel(kind, tihu)`：`TIHU_MODEL_BACKGROUND`（env）> `tihu.model.background`（config）> `null`（跟随默认） |

### 2.3 现场证据（说明"其实已经接上了，但会掉"）

`~/.dsh/tihu/lane.log`（`note=tihu-model`，共 99 条，摘要）：

           这台宿主不能给会话单独指定模型          ← 插件先于宿主服务就绪时的一次性失败

## 4. 最小实现方案（推荐 A 路）

### 4.1 A 路：APK 侧加「指挥台模型」卡（推荐）

**改动 1（必做）：`android/app/src/main/java/com/chenpan/assistant/TihuVoiceUtil.java`**
在 `settingsJs()` 的 `buildPanel()` 里（`:730` 附近，`panelBody.appendChild(makeWakeCard())` 之后）追加 `panelBody.appendChild(makeModelCard())`，并新增 `makeModelCard()`：

- 数据读取：`fetch('/api/assistant/config', {cache:'no-store', credentials:'same-origin'})` → `json.tihu.model.background`
- 列表来源：`fetch('/api/assistant/models')`（`src/assistant.ts:271-290`，为"移动端同源列全部模型"专门加的兜底）→ `catalog.models[{provider, model, name, groupName}]`、`catalog.default`
- 保存：`POST /api/assistant/config`，body
  ```json
  { "tihu": { "model": { "background": { "provider": "...", "model": "..." } } } }
  ```
  置空（跟随 DSH 默认）就发 `"background": null`（`normalizeTihuModelForWrite:329` 接受 null）
- UI：一个 `<select>`（`name` 显示、`value="provider\u0000model"`）+ 一行说明"只影响鹈鹕指挥台会话（不占屏）；已开着的指挥台在下一次连上/派单时切换"；保存后回显 + 一句结果
- 为什么能用：`/tihu` 页与 `/api/assistant/*` 同源且走同一套代理鉴权（`src/pocket-host/index.js:348-365`、`:390-391`；`proxy.mjs:1274` 普通请求原样透传）。**不需要新增宿主路由、不需要改 RPC、不需要动 Java 桥**（纯注入 JS 即可，Java 侧零改动）。

**改动 2（必做，解决 G3/G4）：`src/tihu/lane.ts`（改前先 `copy lane.ts lane.ts.bak-<ts>`）**

```ts
// 现在
const commanderModelApplied = new Set<string>()
async function ensureCommanderModel(sessionId: string): Promise<void> {
  if (commanderModelApplied.has(sessionId)) return
  commanderModelApplied.add(sessionId)          // ← 失败也记成"做过"
  await applyTihuModel(sessionId, 'background', '指挥台')
}

// 改成：按"配置值"记账，成功才记；失败下次重试；配置变了就重放
const commanderModelApplied = new Map<string, string>()   // sessionId → "provider/model"
async function ensureCommanderModel(sessionId: string): Promise<void> {
  let tihu: unknown
  try { tihu = loadAssistantConfig().tihu } catch { tihu = undefined }
  const want = resolveTihuModel('background', tihu)          // model-select.ts:167
  const key = want === null ? 'default' : `${want.provider}/${want.model}`
  if (commanderModelApplied.get(sessionId) === key) return
  if (want === null) { commanderModelApplied.set(sessionId, key); return }   // 跟随默认＝什么都不做
  const ok = await applyTihuModel(sessionId, 'background', '指挥台')          // 返回值改成 boolean
  if (ok) commanderModelApplied.set(sessionId, key)
}
```

- `applyTihuModel` 现在返回 `void`，改成返回 `boolean`（成功/未配置=true，失败=false）；现有两条调用（`:4200`、`:5936`）不受影响。
- 效果：手机端保存后，**下一次 hello / 派单即生效**（不必重启 DSH）；瞬时失败（如 09:25 那种"服务还没就绪"）下次自动补。
- 隔离性：仍然只写 `tihu.model.background`，**从不写 `agentDefaultModel`**（`model-select.ts:118-132` 的快照/恢复逻辑保留），所以电脑端默认模型不受影响；PC GUI 若手动改了指挥台，下一次 hello 会被 lane 按配置纠回来——这是刻意的，需在卡片文案里写明。

**改动 3（可选，纯文案）**
- `src/client/assistant-settings.tsx:512` 标题「默认后台模型」→「指挥台模型（默认后台模型）」，与手机端叫法统一（否则两处名字对不上，用户找不到）。

## 5. 「与电脑端模型选择隔离」的说明（要点）

- 设备侧配置只写 `tihu.model.background`，不碰全局默认：`model-select.ts:104-133` 先快照 `agentDefaultModel.currentSelection()`，选完再 `saveSelection(previous)`。残留窗口极小（官方接口没有 session-only 选项），dsh-orb 的 `code_agent` 也是这么接受的。
- 反向（PC → 设备）：PC GUI 给指挥台换模型会写同一个 `model/selection` 事件；改完 §4.1 后，下一次 hello 会被 `tihu.model.background` 覆盖回来。**这必须写进卡片文案**，否则用户会疑惑"PC 上改了怎么又变回去"。
- 兜底语义清晰：配置为 `null`/未配 → 不做任何事（完全跟随 DSH 默认），与 2026-11-10 之前一致。
