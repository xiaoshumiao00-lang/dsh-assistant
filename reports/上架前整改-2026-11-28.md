### 3.5 第 1 步遗留安全风险（照实列，不改代码，本轮只记录）

1. **旧宿主回退 RPC 通道仍可能回吐密码本体**：`web-rpc.js:63-66` 的 `pocketRequestSource()` 在「RPC 桥没给 `requestInfo.headers`」时直接判本机（reason `legacy-loopback-rpc-channel`）；这条通道走的是旧版宿主（`src/assistant.ts:569-616` 仍经 `legacy-serve.mjs` 回退）。设计上是「老宿主上设置页不能全灭」的妥协，但它等于**在没有来源标记的路径上放弃了来源判定**，`pin.view` 在这条通道会回本体。
2. **`assistant-config` 半边只看 Host 头，没有 TCP socket 地板**：`assistant-config.ts:152-159` 只有当 Host 头缺失时才去看 `req.socket.remoteAddress`（`:154`）；Host 头存在就直接按 Host 头判本机。pocket 侧（`proxy.mjs` 的 `pocketSourceClass`）才有「TCP 源地址给 Host 设下限」这道地板（测试第 6 条断言它存在）——**两侧不对称**。
3. **`GET config` 仍披露危险字段的值**：`allowAllLocalPaths` 与 `allowedRoots` 的**读**没有回环限制（序列化在 `assistant-config.ts:369-370`），只有限制**写**；读到这两个字段等于读出本机目录结构与「边界是否被关掉」的事实。
4. **`pin.setCustom` 允许非回环写入**：`web-rpc.js:403-415` 非回环来源**照做写入**，只是把回显换成掩码元数据——写侧没有地板，读侧有。
5. **`redactStatus` 是透传型 allowlist**：`src/client/pocket/api.js:85-101` 仅 `delete` 掉 `token`（若存在）后按 allowlist 重建；allowlist 里显式包含 `lanUrl`(`:89`)、`lanQr`(`:90`)、`tunnelUrl`(`:94`)、`tunnelQr`、`lanCandidates`、`lanIpOverride`、`tunnelState`、`tunnelConfig`、以及**整个 `sshTunnel` 对象**(`:99`)——即 `sshTunnel` 的 `host` / `user` / `keyName` / `ports` / `lastError` 会整块给到浏览器；`api.js:101-104` 的动态字段正则也仍放行 `…Url` / `…Set` / `…Enabled` 之类。
6. **`fs.list` 仍返回目录结构**：`listDrives()`（`fs-rpc.mjs:158-170`，兜底 `['C:\\']`）与 `listFs()` 返回的 `drives`(`:249-250`)、`crumbs`(`:184`)、`home`/`desktop`、以及每条 entry 的**绝对路径**(`:226-227`)。allowlist 挡的是「读越界」，没有挡「盘符枚举 + 根内目录名 + 绝对路径曝光」。
7. **内存清空的确认词仍是硬编码公开词**：`src/assistant-home.ts:555`、`:639-640`（含客户端面板 `src/client/assistant-memory-panel.tsx:198`，构建产物 `lib/index.js:1444`、`lib/client.js:3538`）。第 4 项只把**逃生开关（allowAllLocalPaths）**的确认词换成一次性口令，memory-clear 这条**没换**。
8. **入口仍是明文 HTTP，无 TLS**：局域网入口是 `http://<本机IP>:3081`（`lanUrl`），公网入口靠 SSH 反向隧道 / Cloudflare 命名隧道；配置模板与手册里给的也都是 `http://` 占位形态。密码在明文通道上跑，靠 8 位 PIN + cookie 而非传输层加密。
9. **`accept-new` 属 TOFU（首次使用即信任）**：第一次见到的主机键会被直接写入 known_hosts，不校验它是否本该是某把已知键；known_hosts 文件本身没有额外访问控制或加密；显式降级 `no`/`none` 仍是可覆写路径（测试第 5 条承认这条覆写余地）。
10. **`0.0.0.0` 被当成回环权威**：`web-rpc.js:48` 与 `assistant-config.ts:155/158` 都把 `0.0.0.0` 判为 loopback（现场 `0.0.0.0:3081` 确在监听，见 4.4）——一个 `Host: 0.0.0.0` 的请求会被判成「本机」。
11. **口令/配置文件落在用户目录，Windows 侧权限口径不硬**：`escape-hatch.json` 的 0o600 在非 POSIX 平台不生效（代码自陈），本机依赖文件系统 ACL；本轮**没有实测该 ACL 的收紧结果**（文件本身还没生成）。

## 13. Computer Use 坐标硬门（2026-11-28）

> 用户新规则原话：「每次思考完之后，点击之前，必须经过脚本把准确坐标计算出来，再点击，这是个人助手插件 Computer Use 的必须步骤」。
> 本轮把它做成插件侧 pre/post-execute 硬门；`vendor/computer-use` 一行未改。

### 13.1 实测失误（本轮证据）

同一 CU 会话，窗口 1920×1032，目标「Publish release」按钮 bbox 实测 (346,888)-(471,917)，中心 (408.5,902.5)。前三次点击都落在按钮左边缘外：

| 次序 | 发送分数 [x,y] | 实际落点（物理像素） | 与 bbox 的偏差 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | [146,873] | (280,901) | 66 px | miss |
| 2 | [171,873] | (328,901) | 18 px | miss |
| 3 | [145,874] | (278,902) | 68 px | miss |
| 4 | [213,875] | (409,903) | 0 px | hit |

根因不是映射错，是**分数靠目测估**：中心应换算为 x = 408.5 ÷ 1920 × 1000 = 212.7604、y = 902.5 ÷ 1032 × 1000 = 874.5155，而前三次 x 分数只有 145–171。

### 13.2 解析器与记录

- 新增 `scripts\cu-coordinate-resolver.mjs`（命令行）与 `src\cu-coordinate.ts`（纯逻辑，测试直接 import）。
- 输入：截图尺寸 WxH、目标 bbox（x1,y1,x2,y2）、可选 bounds、mode（millifraction/pixel）、可选待校验 position。
- 输出：bbox 起止、中心物理像素、0–1000 分数（x/y 各带算式）、建议分数/像素、harness 预测落点（未取整与 round）、check（hit / deviationPx / suggestion）。
- 记录：系统临时目录 `dsh-cu-coordinate-records/<id>.json`，id 为 8 位十六进制，10 分钟过期；不含任何写死的私人路径。

真实算例（仓库相对路径）：

```
node scripts\cu-coordinate-resolver.mjs --shot 1920x1032 --bbox 346,888,471,917 --target "Publish release" --tool click --mode millifraction --position 146,873
```

输出要点：center=(408.5,902.5)、fractions=(212.7604,874.5155)、predictedRounded=(409,903)、check={hit:false, landed:(280,901), deviationPx:66, suggestion.fractions:(212.7604,874.5155)}。

### 13.3 硬门接在哪一步

- 点击请求可见点：宿主 `tools/pre-execute` 的 waterfall 拿到 `exec.name` 与 `exec.arguments`（`arguments` 在进入 policy 前已深冻结）；插件侧在 `src\cu-coordinate-gate.ts:206` 读取 `click / drag / input_text / long_press` 的 `position` / `start_position`。
- 点击结果可见点：同一次执行的 `tools/post-execute` 拿到 `result.value.landed`（vendor 在 `vendor\computer-use\index.js:1339` 写入）与渲染文本 `Pointer landed at [x, y] physical pixels`（同文件 `:1208`）；插件侧在 `src\cu-coordinate-gate.ts:278` 比对 bbox。
- 日志：沿用 `src\turn-guard.ts` 的 `sanitizeTurnGuardLine` 与 `MAX_LOG_BYTES = 200 * 1024` 轮转，写同一个 `dsh-assistant-turn-guard.log`。
- 提示词：`systemPrompt.section` 只在 `agentPreset === computer-use`（或带坐标模式事件）的会话里返回文本，普通会话返回空串。

### 13.4 deny 码与日志字段

| deny 码 | 触发条件 |
| --- | --- |
| `missing-coordinate-record` | 点击类请求没有 `coordinate_record` |
| `coordinate-out-of-bounds` | position 按记录换算后落在 bbox 外（原因里带偏差像素与建议分数） |
| `coordinate-record-stale` | 记录超过 10 分钟 |
| `coordinate-record-invalid` | 记录坏、跨会话复用、坐标口径不一致、id 非法 |
| `coordinate-target-blocked` | 同一 bbox 连续 2 次 miss 后，坐标点击停用 |

日志行字段：`tool` / `code` / `session` / `screen` / `bbox` / `landed` / `deviationPx` / `streak` / `record` / `advice` / `textChars`。日志不落目标文本（没有 excerpt）、不落本机绝对路径；`textChars=` 一律为 0（只落计数，不落正文）。

### 13.5 与 `scripts\test-coordinate-mode.mjs` 的关系

该脚本 6/6 断言的是**坐标模式设置层**：没有配置时按平台缺省、POST 写盘后服务与 GET 同步、已有配置继承、非法 body 400、服务 setter 与路由共用状态、vendor 优先读 `assistantCoordinateMode`。它不是覆盖层时代的旧口径，也不校验归一化映射公式；它守的是「会话用 0–1000 还是截图像素」这条契约。本轮的硬门依赖这条契约（记录 `mode` 必须与会话口径一致），但两者不同源、互不替代；未改该脚本任何断言。
