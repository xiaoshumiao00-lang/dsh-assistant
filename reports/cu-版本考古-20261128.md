# CU「点击前固定脚本算坐标」版本考古（只读取证，2026-11-28）

**一句话结论**：最可能是 **2026-11-26 定版的「固定脚本测量 → 算 fraction → 一次点击」这一版**——脚本 `measure.ps1`（sha256 前 8 位 `b960ab57`）读最新截图、按颜色阈值与像素间隙切出目标 bbox，直接打印 `center=(x,y)` 与 `fraction=[x,y]`，模型按这个数点一次就完。这一版**没有 git 提交**（脚本落在仓库外的用户主目录 scratch 目录，用法写进了运行时记忆条目「GUI 点击铁律」）；仓库侧可引用的锚点是 2026-11-25 的 `6840335`（默认坐标系改截图原始像素）与 2026-11-20 的 `7e8fc52`（vendor 侧落点精确化：多屏虚拟桌面映射 + 指针回读校验）。

```
+	if (host.foregroundWindowId() !== target.windowId && !host.focusWindow(target.windowId)) throw new Error(...)
+const WS_EX_NOACTIVATE = 2048;
+	BringWindowToTop: user32.func("int __stdcall BringWindowToTop(void *hWnd)"),
```

即 11-20 改的是**焦点回读 + 多屏映射**两件事：前者按 `GetForegroundWindow` 的实际结果判定目标是否在前台（顺带解决「为了抢焦点发 Alt、反而把前台带走」）；后者用虚拟屏四指标 + `MOUSEEVENTF_VIRTUALDESK` 表达负原点，并在 `SetCursorPos` 之后 `GetCursorPos` 回读比对、不一致就抛错、再退 `SendInput`。落到「点得准」上是**把系统性错位与静默失败干掉**：

```
+		if (api.SetCursorPos(x, y) !== 0 && api.GetCursorPos(pos) !== 0 && pos.x === x && pos.y === y) return;
+		if (api.GetCursorPos(pos) === 0 || pos.x !== x || pos.y !== y) throw new Error(`computer-use: pointer input failed (wanted ${x},${y}; got ${pos.x},${pos.y})`);
```

**判断**：11-20 这批是「落点保真」（让请求的那个像素真的落到那个像素），11-25 是「坐标口径」（让模型给的两个数不再需要换算）。两者都是「点得准」的必要条件，但都不是「点击前由固定脚本算出坐标点」——那一环在 11-26：`measure.ps1` 把 bbox 中心直接算成 `center` 与 `fraction`，模型只负责照数点一次。三者叠起来才是用户记忆里「又快又准、一次就点准」。
