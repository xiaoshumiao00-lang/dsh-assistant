# 发布说明 · 插件 0.2.42 与安卓壳 1.4.10

口径来源：仓库 `CHANGELOG.md` 的 `## [0.2.42]` 与 `## [0.2.41]` 两节、`package.json` / `dsh.plugin.json`（同为 **0.2.42**）、
安卓壳 **1.4.10 / versionCode 37**。按本轮纪律，这份说明只用类别名，不写已作废的旧口令、旧入口地址，也不写本机账户名、
作者姓名拼音与中文姓名那一类个人化标识；需要指向某台机器或某把证书时，只给 sha256 指纹。

## 1. 这一版改了什么

### 插件 0.2.42（相对 0.2.41）

- **本轮只有版本口径与文档口径收口**：`package.json` 与 `dsh.plugin.json` 0.2.41 → **0.2.42**，CHANGELOG 新节，
  上架包五处口径同步（交付清单 / 产品文案 / 本文件 / 手册 / 自检.ps1）+ 规格件示例值。`src` 侧零改动、`package-lock.json` 未动。
- **安卓更新回归已接进 test 链**：1.4.10 那笔 commit 把 `scripts/test-android-update-check.mjs` 加进 `package.json` 的 test 串（96 → **97** 条）。
- **上架动作本轮授权**：push `main`（fast-forward）+ 附注 tag `v0.2.42` + 轻量 tag `android-shell-1.4.10`，
  两枚旧 tag（`v0.2.41` / `android-shell-1.4.9`）保留不动；不重写历史、不强推、不动远端其它分支与设置。
- **「检查更新」的硬依赖是 GitHub Release**（现场实测，见第 1 节那条与手册第 5.1 节）：壳只读 `releases/latest`；
  只有 tag 没有 Release 的仓库会 404，壳照实提示「这个仓库没有 release」，不会自动去读 tag。

  `markdown-it` 只有客户端一处 `new MarkdownIt({ linkify: true })` + `.render()`（没有插件注册，没有 `html` / `typographer` 选项），
  两个包本轮都是 patch 级变动，**src 侧不需要 API 适配**。
- **上架包素材补齐**：`素材\` 里新增插件图标 128×128 / 256×256 / 512×512 与横幅 1600×400（主口径）/ 1280×400（备选），

- **版本号口径统一**：`package.json`、`dsh.plugin.json`、`CHANGELOG.md` 新节、上架包四份文档（本文件、`交付清单.md`、

### 安卓壳 1.4.10（相对 1.4.9）

新增功能：**「检查更新」+ 一键下载安装**，全部默认关闭、默认不联网。

- 查询：只有用户主动点（后菜单第 4 项「检查更新」或设置页那颗按钮）才发**一个**请求，
  host 必须是 `api.github.com`、协议必须是 https、不许带端口/userinfo/查询段、不许跟重定向跑；
  开关关着、更新源空着、更新源不合规、24 小时内已查过 —— 这四种情况**一个请求都不发**。
- 更新源：只有 `owner/repo` 形态（你自己的 GitHub 账号名/仓库名）；填别的形态一律被拒并且照实说明「没有发出任何请求」；
  留空就是关闭，壳里没有任何预置源，也不查别人的仓库。
- 节流：24 小时只查一次（与插件侧同口径）；「这版不装」写进持久化的忽略项，同一个版本从此不再提示，可在设置页清掉。
- 失败照实报：403（限流/要登录）、404（这个仓库没有 release）、非 2xx、JSON 读不出、tag 空、release 里没有 APK
  —— 都报成失败并说明原因，**绝不伪装成「已经是最新版」**。
- 下载安装：复用系统原生下载（`DownloadManager`），完成后用 DownloadManager 的 `content://` Uri 发
  `ACTION_VIEW` + 临时读授权 + `application/vnd.android.package-archive` → **系统安装界面**；
  没有新增 FileProvider、清单权限净新增 0 项、不静默安装。Android 8+ 没允许「安装未知应用」时先说清、只给跳系统设置页的入口。
- 隐私面：不遥测、不后台自动查、不定时唤醒；一次点按只发一个请求，请求跑在后台线程，UI 不被卡住。
- **「检查更新」的硬前提：用户自己的仓库必须有 1 个 Release，且 APK 挂成它的资产**（现场实测口径，不是推测）：
  壳只读 `https://api.github.com/repos/<owner>/<repo>/releases/latest` 并从中拿 `tag_name` 与资产里的 `browser_download_url`；
  只带 tag 不带 Release 的仓库这条地址回 **404**（实测：`/releases/latest` = 404 `Not Found`；`/tags` = 200 列出 tag；`/releases` = 200 且空数组），
  壳于是提示「这个仓库没有 release」，**不会去读 tag**（`UpdateCheck` 里没有读 tag 的分支）。对照一个带 Release 的公开仓库，
  同一个 `/releases/latest` 回 200 且带 `tag_name` + `assets`。买家要能用这条链，就必须在 GitHub 网页（或 `gh release create <tag> <apk 路径>`）
  先建 Release 再把 `.apk` 拖进 Assets 上传、Publish。完整步骤写在《安装与部署手册》第 5.1 节「第 0 步」。
  本轮**没有**在 GitHub 网页创建任何 Release（那一步要用户单独确认，由前台会话做）。
- versionCode **36 → 37**，versionName **1.4.10**，minSdk 24 / targetSdk 34 未变；包名沿用（含作者姓名拼音段，按纪律不写全）。
- 签名仍用同一把 keystore（证书指纹 `b081dc7ba8a54c2fa36ab4f8bffcabedcd9558d922dcea8dcac21cfe04b7a333`）→ 老用户覆盖安装成立。
- 实测字节与哈希见《交付清单》第 3 节（本轮现场取实）。

## 2. 安全整改摘要（0.2.40 那一轮的 4 项，本轮沿用）

1. **SSH 主机键边界**：反向隧道的两处参数组从「不校验」改成 `accept-new`，known_hosts 换成真实可写路径（可被 env 与 settings.json 覆写，非法值回落默认，exec/spawn 前建目录）。
2. **访问口令不再回显**：`status` 只报「是否已设置 + 长度掩码」；口令本体只走对**本机回环**可用的那条路由；公网来源轮换后只给掩码，不给原始 PIN；来源判定不到即按非本机（fail closed）。
3. **手机文件通道接目录 allowlist**：目录列表 / 文件读取 / 上传保存三条通道全部过同一份边界，拒绝时带明确错误码；拆边界的两个危险字段**只有本机回环能写**。
4. **一次性逃生口令**：确认词不再是源码里的公开字面量，改成运行时生成的随机值（本机私有文件、0o600、原子替换），只在本机回环那条路由打印，用完即刻换新，比对走定长比较。
5. 本轮另加的日志卫生：判定日志只落标识（不落回复正文、不落本机绝对路径），超 200 KB 自动轮转 `.1`，行内截到 240 字符；尾快照带上限；诊断包导出前统一脱敏。

**轮换口径**：上一轮已作废的那套访问口令与旧入口地址（本轮档案里一律写作「旧口令」「旧入口 A / 旧入口 B」）都不再有效；
新口令只在本机配置与商店交付包里由用户自己设置，仓库与构建产物里不含明文。签名口令不在仓库内，只存在于仓库外的本机私有文件
（`release\上架包\交付清单.md` 只登记它的长度与指纹前 8 位）。

## 3. 升级路径

- **安卓壳覆盖安装成立**：1.4.10 与 1.4.9 / 1.4.8 用**同一把签名密钥、同一份证书**（指纹 `b081dc7b…b7a333`），
  versionCode 36 → 37 递增，因此从 1.4.9 直接装 1.4.10 的 APK 是覆盖安装，不需要先卸载，也不影响已配的助手地址与会话数据。
- **1.4.10 手机上就能自查更新**：先在应用里按系统「返回」键（回到页面首页那一步会弹出「设置地址 / 重新加载页面 /
  退出应用 / 检查更新」这个菜单）选「检查更新」，或打开设置页（同一份菜单第 1 项）里「检查更新」那一区块，
  先把开关打开、再填你自己的 `owner/repo`。默认关着的时候这个应用完全不联网。装新版要在系统弹出的安装界面点「安装」确认（应用没法自己静默装）。
- **插件侧升级**：0.2.40 → 0.2.41 只是依赖版本与文档口径，功能面不变；0.2.41 → 0.2.42 同样只有版本口径与文档口径（本轮没有 src 改动）；宿主侧改动**需要重启 DSH 才生效**。
- 构建产物本轮实测字节：`lib\index.js` 563,510（不变）、`lib\pocket.js` 238,309（不变）、
  `lib\client.js` 1,718,330 → 1,700,986（0.2.41 那轮：15.0.3 的解析器精简 + 公告正文换成 0.2.41 那一节）→ **1,701,064**（0.2.42 本轮：公告正文换成 `## [0.2.42]` 那一节，+78 字节）。
- 质量门现场（1.4.10 本轮实测，数字与回报正文一致）：`node build.mjs` exit 0、`npm run check` exit 0、
  全量测试链 **97 条**（上一轮 96 条，本轮接入 `scripts/test-android-update-check.mjs`），总数/通过/失败按本轮现场取实；
  红项只有基线那两条（`test-secretary-session-log-write`、`test-mobile-proxy`），本轮没有新增红项；
  本轮新增那份回归 20/20、基线 CU 脚本 8 份 exit 0、安卓 2 份 15/15 与 25/25、
  `lint-standards` 抱怨 0 条、`typecheck` 条数与 `node scripts/typecheck.mjs` 现场值一致（见回报正文）。
