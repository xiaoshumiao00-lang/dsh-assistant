# 素材说明（上架包里的 10 张图）

包内素材目录：`素材/`。命名口径：`shot-0N-*` = **脱敏后的真实宿主界面截图**；`mock-0N-*` = **合成示例图**（不是真实界面）。

## 遮罩口径（先读这一节）

真实截图的来源帧是**作者这台机器跑着的宿主真实界面**，落盘前后做了「固定矩形遮罩」处理，不是裁剪也不是重新绘制：

| 遮罩 | 矩形（x1,y1,x2,y2，像素） | 填充色 |
| --- | --- | --- |
| 左侧会话栏（会话标题与列表） | `0, 0, 292, 821` | `(246, 247, 249)` |
| 模型芯片（模型名与用量） | `640, 486, 1060, 540` | `(246, 247, 249)` |
| 卡片正文（秘书卡片正文区） | `470, 424, 1058, 652` | `(246, 247, 249)` |

遮罩是**固定矩形**，同一次采集的所有帧用同一组坐标；填充一律用同一个浅灰色（246,247,249），
所以图上被遮的地方一眼能看出来（灰块 = 遮罩），不会出现「看不出被遮了」的情况。

## 为什么 shot-I / shot-L 不进上架包

- `shot-I-controlroom-cards.png`、`shot-L-interface-entries.png` **不进包**。
  原因：这两张把**作者本机真实项目卡片名**渲染出来了（卡片标题就是这台电脑上真实项目的名字）。
  卡片正文遮罩矩形（`470, 424, 1058, 652`）盖的是「正文区」，而**卡片标题与卡片名不在那个矩形里**，
  所以这两张即使按同一套遮罩处理，项目名仍然露在外面 —— 换人拿这套素材也用不上，还会泄作者的项目结构。
  控制室与界面入口的对外展示改用合成图 `mock-09` / `mock-10`（占位名，不含真实卡片名）。
- 同样地，采集清单里没进包的其余帧（`shot-H-secretary-view.png`、`shot-J-plugin-desc.png`）只留在
  `outputs/` 工作目录里，不进上架包 —— 上架包只用上面这 8 张。

## 2 张合成图（不是真实界面）

这两张**不是截图**，是我写的 mock HTML 用 headless Chrome 渲染出来的示例图：

| 文件 | 尺寸 | 字节 | 来源 |
| --- | --- | --- | --- |
| `mock-09-controlroom-cards.png` | 1280×560 | 47,886 | `.tmp/mock-controlroom.html` → `chrome.exe --headless=new --screenshot --window-size=1280,560 --virtual-time-budget=4000` |
| `mock-10-mobile-access.png` | 390×844 | 40,153 | `.tmp/mock-mobile.html` → 同一套命令，`--window-size=390,844` |

两张图上都有一条显眼的橙色横幅写着 **「⚠️ 合成示例数据（MOCK）」**，卡片名一律是
**示例项目A / 示例项目B / 示例项目C**（会话行写「示例会话A…D」），手机端入口地址写作
`http://<你的电脑IP>:7080` —— 尖括号是占位符，不是真实 IP。
**上架时必须保留这种「合成示例数据」标注**，别裁掉、别再截一张真的盖在同样的文件名上。

## 上架包素材的红线

- 不出现真实 IP、真实域名、真实账号 ID、真实 PIN、一次性口令、token 值；
- 不出现作者本机私人路径与真实项目卡片名（shot-I / shot-L 就是为此被挡在包外）；
- 不用 npm 名 `dsh-assistant` 的截图（那是别人的同名包）；
- 素材一律是 PNG，别改成长名再重新压缩（改名会破坏「尺寸/字节」这张表的对应关系）。
