# 图标与横幅规格件（上架包 · 本轮新增）

本轮（0.2.41 那轮）实做出来的东西：**3 个插件图标 PNG + 2 张横幅 PNG + 本规格件**。
下面所有数字都是本机现场实测（文件字节 + PNG IHDR + `sha256`），不是设计稿口径。

## 2. DSH 插件侧的真实字段名（不是猜的，取自本机 DSH 文档口径）

- 图标字段有两个合法写法，**顶层字段优先**：
  - `package.json` 顶层 **`icon`**，值必须是**相对清单目录**的包内路径（绝对路径、URL、软链接一律被拒）；
  - `package.json` 的 `exports` 里 **`"./icon"`** 这条导出（子路径插件用 `"./<subpath>/icon"`）。
- 允许的格式：**SVG / PNG / JPEG / WebP**；**上限 256 KiB**；文件必须留在包内。
- 打包白名单：`files` 数组里要**列出这张图标**（连同补丁、locale、docs 一起列），否则 `npm pack` 出来的包里没有它。
- 插件详情页文案的真实字段：`locale/en.json`（以及其它语言那份 locale）里的 **`meta.title` / `meta.description` / `meta.detail`**；
  对应导出要包含 `./locale/*.json` 与 `./icon`。
- 详情页正文的限制口径：Host 侧 `pluginManager.detailMaxBytes` = **1 MiB**，
  详情页配图 `pluginManager.detailImageMaxBytes` = **5 MiB**。
- 详情页那张「功能图」的口径是 **SVG，`width="640" height="300" viewBox="0 0 640 300"`**，
  在 detail 文档里只用一行图片引用（`![...](<那张 svg>`）。
  → **横幅在 DSH 插件侧没有对应字段**：DSH 只有「图标」和「详情页功能图（640×300 SVG）」两类图像，
  1600×400 / 1280×400 那两张是**给第三方商店与自建站 hero 用的素材**，不是清单字段。
- 图标绘制的官方口径（我们这张已按它做）： artwork 建议 `width="36" height="36" viewBox="0 0 36 36"` 的构图比例、
  **不铺底色方块**、颜色克制、**不加发光/阴影/emoji**、字形要转成路径、空心部分要**真透明**。

**本轮仓库现状（现场核对过）**：`package.json` 与 `dsh.plugin.json` 里**都没有 `icon` 字段，也没有 `./icon` 导出**，
仓库里也没有 `locale/` 目录与 `meta.*` 字段——所以**插件侧没有图标字段，规格件只进上架包**；
把图标真正接进清单（改 `package.json` 的 `icon` / `exports` / `files`）属于下一轮的清单改动，需要单独一次 commit，
本轮不动插件结构，也就没有破坏 `npm run check` 的口径。

## 3. 下一轮把图标接进插件时该填什么（真实字段名 + 示例值，可直接照抄）

把 `icon-256.png` 复制到仓库根目录改名 `icon.png`（清单同级），然后：

```json
{
  "name": "dsh-assistant",
  "version": "0.2.41",
  "icon": "./icon.png",
  "exports": {
    "./icon": "./icon.png"
  },
  "files": [
    "./icon.png"
  ]
}
```

（`exports` 与 `files` 里已有的条目不动，只是**追加**这条；`icon` 顶层字段与 `./icon` 导出二选一也能工作，
但两处都写会让「顶层优先」与「导出可解析」同时成立。）

如果改走 `dsh.plugin.json` 那条入口，同名字段 `icon` 也照上面写法填；
配套的语言文案真实字段是 `./locale/en.json` 里的 `meta.title` / `meta.description` / `meta.detail`，
需要同时把 `"./locale/*.json": "./locale/*.json"` 与 `"./icon"` 写进 `exports`。

## 4. 商店审核常见尺寸要求（写死的具体值，不留「待确认」）

| 上架目标 | 图标 | 横幅/推广图 | 截图 | 来源口径 |
| --- | --- | --- | --- | --- |
| Chrome 应用商店（扩展） | 必需 **128×128 PNG**：真实图案 **96×96**，每侧留 **16 px** 透明留白；不得加边框、阴影 | 小推广 **440×280**、marquee **1400×560** | **1280×800** 或 **640×400** | [Chrome Web Store 图像文档](https://developer.chrome.com/docs/webstore/images) |
| Firefox 加载项（AMO） | 列表图标 **128×128**（PNG 或 JPEG）；包内图标 **32 / 64 / 128** | 无横幅字段（列表横幅用截图） | 最大展示 **1280×800**，其它比例建议 **1.6:1** | [Extension Workshop · 上架素材指南](https://github.com/mozilla/extension-workshop/blob/master/src/content/documentation/publish/create-an-appealing-listing.md) |
| Google Play（安卓壳 APK） | **512×512**，**32 位 PNG**、sRGB、上限 **1024 KB**、**完整正方形**；Play 会自动套 20% 圆角遮罩与阴影，所以**原图不加圆角/阴影** | 商品详情图 **1024×500**（JPEG 或 24 位 PNG，**不带透明**） | 手机截图竖版 | [Google Play 图标设计规范](https://developer.android.google.cn/distribute/google-play/resources/icon-design-specifications) |

**这张表和本轮素材的对应关系**：
`icon-512.png` 直接可用作 Google Play 图标（512×512、RGBA 8-bit、16,380 字节 << 1024 KB）；
`icon-128.png` 直接可用作 Chrome 扩展图标与 AMO 列表图标（128 外框内图案实际占 0.13–0.87，四周留白 ≈17 px，已满足「96+16」这一口径）；
`banner-1600x400.png` / `banner-1280x400.png` 是自建站 hero 与商店 4:1 横幅的**本轮主口径**，
如果要送 Chrome 现行 marquee（1400×560）或 Play 商品详情图（1024×500），
按第 1 节那套分数坐标与调色重跑同一张几何图即可（同一设计不放大、不裁切内容），不需要重新设计。

## 5. 素材红线（沿用 `素材说明.md` 的口径，本轮新增素材同样受它约束）

- 不出现真实 IP、真实域名、真实账户名/姓名、真实账号 ID、真实 PIN、一次性口令、token 值；
- 不出现作者本机私人路径与真实项目卡片名；
- 不用同名 npm 包的截图；
- 素材一律 PNG（详情页功能图那一件例外，它要求 SVG）；文件名带尺寸就不改名，改名会破坏本表「像素/字节」对应关系。
