# 报错对照表（只列源码里真实存在的错误码）

每条都在源码里对得上；源码位置写在括号里，你可以自己 grep 核对。
**没在源码里出现过的码一律不列**——如果界面上出现了这里没有的串，那是宿主或别的插件给的消息，请连诊断包一起反馈。

状态码缩写：400 请求内容不对 / 403 拒绝（边界或来源判定）/ 404 找不到 / 405 方法不对 / 409 冲突 / 413 太大 / 500 内部错误。

## 1. 目录边界与文件访问

| 码 | 现象 | 原因 | 该怎么办 |
| --- | --- | --- | --- |
| `outside-allowlist` | 内容窗或手机「电脑文件」列目录 / 读写文件时 403，提示里带一个绝对路径与一句「在设置里加上这个目录」 | 这个路径不在**目录 allowlist** 的允许根之内（`src/path-guard.ts:138`、`src/index.ts:510`） | 在电脑上打开 设置 → 个人助手 → 本机配置 → 目录边界，把提示里那个目录（或它的父目录）加进 `allowedRoots`，保存即生效（不用重启）。手机/公网来源不能改这项，见第 2 节 `loopback-only`。 |
| `drive-root-denied` | 列 `C:\`、`D:\` 或 `/` 直接被拒 | 整盘根单独一类拒绝（`src/pocket-host/fs-rpc.mjs:27`、`isVolumeRoot`） | 换成盘里的具体目录（如 `D:\你的项目`）。要整盘都放行只有逃生开关（第 2 节），但那是危险操作。 |
| `path-traversal-denied` | 入参里带 `..` 的路径被拒；上传时拼出来的落盘路径跑到 uploads 目录之外也被拒 | 拒绝 `..` 遍历（`fs-rpc.mjs:28`、`:78`、`:293`） | 用绝对路径或 `~/` 开头的路径，别自己拼 `..\..\`。上传只放文件名，不要带路径。 |
| `empty-path` | 路径栏是空的 / 路径解析非法 | `src/path-guard.ts:123`、`fs-rpc.mjs:29`、`:73` | 填一个具体目录；留空想按默认根走就先试 `~/`。 |
| `missing path` / `not a file` / `not found` | 文件路由报 400 或 404 | 没给 `path` 参数、给的是目录、文件不存在（`src/index.ts:430`、`:435`、`:588`） | 检查是不是复制了相对路径；先在电脑上确认文件存在。 |
| `file too large`（413，带 `maxBytes`） | 点开附件时提示太大 | 本机文件读取上限 **100 MB**（`src/index.ts:407` `LOCAL_FILE_MAX_BYTES`、`:438`；静态托管另一道 40 MB 上限 `:589`） | 把文件切小，或在电脑上直接打开那个文件。上限是插件的，不是手机的。 |
| `content too large`（413） | 从手机写文本文件被拒 | 写入内容上限 20 MB（`src/index.ts:702`） | 分段落盘，或到电脑上改。 |
| `missing root` / `outside root`（400/403） | 本地站点静态托管报错 | 没带 root 令牌，或请求路径跑到挂载根之外（`src/index.ts:577`、`:581`） | 别手工改 URL；从界面里的目录条目点开 `index.html`。 |
| `parent not found` / `not a directory` / `directory not found`（400/404） | 新建/列目录报错 | 父目录不存在，或给的路径不是目录（`src/index.ts:726`、`:761`、`:763`） | 先在电脑上把父目录建出来。 |
| `文件名非法` / `附件为空` / `附件过大（上限 25 MB）` / `附件数据非法（需 base64）` | 手机上传文件报错 | 上传三道闸（`fs-rpc.mjs:272`、`:277`、`:279`、`:281`；上限常量 `MAX_UPLOAD_BYTES`） | 改文件名（别用 `con`/`nul` 这类 Windows 保留名），换小文件（>25 MB 走电脑上拷贝）。 |
| `invalid-projects`（400） | 跨端状态保存报错 | `PUT /api/assistant/state` 的 `projects` 不是对象（`src/assistant-store.ts:135`） | 刷新页面再保存；别手工发这个请求。 |
| 409 `conflict: true` | 保存项目列表时「另一端改过了」 | 乐观并发控制：宿主 `revision` 比你带来的基线新（`src/assistant-store.ts:409`） | 采纳宿主那份（客户端会自动改成采纳），别两个人同时改。 |

## 2. 本机配置与逃生开关

| 码 | 现象 | 原因 | 该怎么办 |
| --- | --- | --- | --- |
| `loopback-only`（403） | 从手机/公网想改「目录边界」或「逃生开关」，被拒且带 `field` 名 | `allowAllLocalPaths` / `allowedRoots` 只允许**本机回环**写；经 pocket 代理进来的来源标记是 `lan` / `public`，或带 `cf-connecting-ip`，或 Host 不是回环（`src/assistant-config.ts:112`、`:663-674`、判定 `requestLoopback`） | 到这台电脑上改。这是设计，不是 bug：手机带 PIN 登录过也不能拆边界。 |
| `loopback-only`（403，逃生口令路由） | 按「🔑 取一次性口令」时手机侧 403，且不回吐口令本体 | `GET /api/assistant/escape-hatch` 只在本机回环答话（`src/assistant-config.ts:719-727`） | 在本机浏览器里打开 DSH 的设置页取口令。 |
| `confirm-required`（400，带 `field: allowAllLocalPaths`） | 把逃生开关拨到「关边界」保存时 400 | 需要带**本机一次性口令**；口令不在源码/仓库/构建产物里，`~/.dsh/assistant/escape-hatch.json`（0o600），一次一换（`src/assistant-escape-hatch.ts`、`src/assistant-config.ts:679-688`） | 在同一台电脑上按「取一次性口令」，把那串（24 位）粘进确认框保存。用成功一次就换新口令。**不要把它抄进任何文件或聊天记录。** |
| `unknown-field`（400，带 `field` 名） | 保存本机配置时被拒 | 字段不在白名单（`src/assistant-config.ts:92`、`:415`） | 只改有的字段：`newProjectParent` / `skillRoot` / `asrTerms` / `allowedRoots` / `allowAllLocalPaths` / `persona` / `termEnvAllow` / `updateSource` / `updateCheckEnabled`。 |
| `expected-object` / `config-not-object` / `nothing-to-change` | 保存时报请求体不对 / 没改动 | 校验与去空改动（`src/assistant-config.ts:409`、`:547`、`:495`、`:540`） | 别手发空请求；界面里改一项再保存。 |
| `config-unreadable` / `config-unreadable: <原因>` | 本机配置文件读不出来 | JSON 坏 / 权限问题（`src/assistant-config.ts:552`） | 用备份还原，或删掉 `~/.dsh/assistant/config.json` 让插件按默认重建。 |
| `write-failed: <原因>`（500） | 保存失败 | 原子写（tmp→rename）失败（`src/assistant-config.ts:571`） | 看磁盘空间与文件权限；别把配置文件放在只读目录或被占用。 |
| `hatch-write-failed` / `hatch-unreadable`（500） | 取一次性口令失败 | 口令文件写不出 / 读不出（`src/assistant-escape-hatch.ts:75`、`:92`） | 检查 `~/.dsh/assistant/` 是否可写；删掉 `escape-hatch.json` 会当场重新生成。 |
| `too-large`（413）/ `empty-body`（400）/ `invalid-json`（400） | 保存请求被拒 | 请求体大小闸（上限 4096B~4MB 视路由）、空 body、不是合法 JSON（`src/assistant-config.ts:596`、`:602`、`:606`；`turn-guard.ts:596`） | 别手工发；界面上分次改。 |
| `包太大（上限 48MB）` / `body 不是合法 JSON`（413/400） | 助手档案导出/导入报错 | 归档包上限 48 MB（`src/assistant-archive.ts:36`、`:340-341`） | 先清理大的 `outputs/` 内容再导出。 |
| `body-too-large`（413）/ `need-target` / `need-content` / `need-confirmation`（400）/ `method`（405） | 助手家目录写入 / 清空报错 | 助手家目录路由的参数与确认闸（`src/assistant-home.ts:616-640`） | 「清空全部」要确认词 `DELETE-ALL`（界面上按按钮会带）；其它一律回界面里做。 |

## 3. 手机访问握手（HTTP 状态）

| 现象 | 原因 | 该怎么办 |
| --- | --- | --- |
| 手机浏览器一行 `dsh web authentication required`，或 API/WS 一直 401 | pocket 代理对没有凭证的 `/api/*` 与 WebSocket 一律 401（`src/pocket-host/proxy.mjs:584`；`web-rpc.js:280` 回 `unauthorized` / `forbidden`）。DSH 重启后代理端口与握手 token 会变，旧 cookie 失效 | 用 1.0.2 起（含现在 1.4.8）的 APK：它会自动带 cookie 修复；浏览器侧访问 `http://<你的电脑IP>:3081/?dsh-pocket-auth=1` 强制重做一次握手；或直接重新输一次访问密码。 |
| 主页 200 但里面白屏 / 子资源 401 | 握手只给了主页凭证，路径漏判（`proxy.mjs:510` 的 issue #35 口径） | 刷新一次；仍不行就 `/?dsh-pocket-auth=1` 重做握手。 |
| 登录后回到首页但你的布局设置被吞了 | 登录跳转只保留 `dsh-pocket-auth=1`，`token`/`dsh-pocket-retry` 被剥（`proxy.mjs:662-724`） | 把布局选择在设置里重做一次；这是已知口径。 |
| 403（Host/Origin 栅栏）普通浏览器刷新后直接打不开 | 代理的 Host/Origin 判定把这条请求判为 `denied`（`src/pocket-host/index.js:362`、`proxy.mjs:77`） | 别用别的域名/端口转发套它；直接访问代理给的那条地址；本机回环判定见第 2 节。 |
| 屏幕上大字提示「DSH 桌面端处于 advanced 模式，手机访问暂不支持」 | 桌面宿主在 advanced 模式，pocket 不接（`proxy.mjs:145`） | 在桌面端设置里切回 **compatibility** 模式后重启宿主。 |
| 插件启动失败，日志里 `EADDRINUSE`（3081） | 默认端口 3081 被同机另一个 DSH 或别的服务占了（`src/pocket-host/index.js:348-349`） | 在电脑上改 `proxyPort`（1–65535）后重启宿主。 |
| 语音输入没反应 / 麦克风拒绝 | 纯 `http://IP` 入口浏览器不给麦克风（`src/client/pocket/orb/locales.ts:148` `Microphone permission denied`） | 用 https 入口（Cloudflare 命名隧道或自己的证书），或在本机 `localhost` 上用。 |

## 4. 安卓附件下载（1.4.x 相关）

| 现象 | 原因 | 该怎么办 |
| --- | --- | --- |
| 点 Word/PDF 附件后通知栏**一直「正在下载」**，永远下不完 | 系统 DownloadManager 不继承 WebView 的 cookie 罐；pocket 对无凭证的 `/api/worktable/file` 回 `401`（24 字节、`chunked`、**没有 content-length**），下载器既拿不到文件也拿不到总字节数 | 装 **1.4.5 起**的 APK（`CookieManager` 取 cookie 并 `addRequestHeader("Cookie", …)`，已修）。你手上这份是 1.4.8，已含该修复。别用旧壳版本。根因与取证见仓库 `docs/安卓附件下载-401-根因-20261126.md`。 |
| 图片点开变成刷新页面 | 1.4.6 起图片也走原生下载链路（`download=1` + 服务端强制 `attachment`） | 正常现象；下载完会拉起系统看图应用。 |
| 附件点了没反应 / 提示「这个文件要到电脑上下载」 | `DownloadManager.enqueue()` 拿到的 URI 不可解析（旧壳的 catch 兜底文案） | 更新 APK；或用手机浏览器打开同源地址再点。 |
| apk 附件下载后要装但被拦 | 清单已加 `REQUEST_INSTALL_PACKAGES`（1.4.7 起） | 在系统弹窗里允许一次「未知来源」。 |

## 5. turn-guard（防空转补步）的状态词

这些**不是 HTTP 错误码**，是判定日志里的状态词（`src/turn-guard.ts`）。
日志文件：`<profile 目录>/dsh-assistant-turn-guard.log`（超过 **200 KB** 自动轮转到 `.1`，只留 1 份；行内最长 240 字符；不落回复正文、不落本机绝对路径）。
开关真值：`<profile 目录>/dsh-assistant-turn-guard.json`，读写走同源 `GET/POST /.dsh-assistant/turn-guard`（`turn-guard.ts:28-29`、`:53-55`、`:66`、`:70`）；界面在 设置 → 个人助手 → 托管，点完立即生效。

| 状态词 | 含义 | 用户该怎么办 |
| --- | --- | --- |
| `branch=disabled` | 开关是关的，本轮不补步（`turn-guard.ts:679`） | 想让它续跑就在托管里把开关打开。 |
| `branch=no-agent` | 这次收尾不属于 agent 循环（`:685`） | 不用管。 |
| `branch=preset-skip` + `preset=<名字>` `allowed=[...]` | 这条会话的预设不在允许列表里，按预设跳过（`:691-692`） | 在托管里把该预设加进允许列表，或换回允许的那个预设。 |
| `branch=cap` + `injected=n/上限` | 同一个 **turn** 内补步已达 `maxPerTurn`（默认 3）（`:314`） | 任务本身有问题的话，别指望它无限补；看日志里同一个 turn 号下反复的 leak 判定，回界面检查模型输出。配额按 turn 计（跨 turn 自动重置）。 |
| `branch=leak`（`reason=leak`） | 最后一条 assistant 文本里有**以**工具调用标记开头的行（写成纯文本了），补一步（`:317`） | 正常会自动补；一直红说明这个模型在长上下文里漏结构化 tool-call，考虑换模型或缩短任务。 |
| `branch=empty`（`reason=empty`） | 只有 reasoning、正文为空（`steerEmptyText` 生效时）（`:318`） | 同上。 |
| `branch=toolcall` / `text-ok` / `no-assistant` / `fallthrough` | 有结构化 tool-call / 正常正文收尾 / 没有 assistant 消息 / 不匹配任何判据（`:199`） | 不用管。 |
| 纠正消息前缀 `[turn-guard]` | 补的那一步注入的消息标记（`:51`） | 在会话里看到它就说明这一轮被续跑过；它是插件自己发的，不是用户消息。 |
| `steer turn=N ... injected=已补/上限 dayInjected=当日已补 scoped=turn|session` | verdict 行完整版（`:702-703`） | 排查「上一轮好了这轮又停」时看这行。 |
| 「宿主没有事件总线（ctx.on 不可用），turn-guard 未启用」 | headless / 无事件总线的 profile（`:663`） | 在有完整桌面的 profile 上用。 |
| 日志 `已挂载 turn-guard 路由 GET/POST ...（状态文件 ...）` 或 `turn-guard 路由挂载失败（开关仍按状态文件生效）` | 路由注册成功/失败（`:768-770`） | 挂载失败也不影响开关：真值在状态文件里，可直接在本机改。 |
| 历史闸：即将写会话日志的 user/message 缺 id 就地补 uuid（`:33-35`） | 缺 id 会让整条会话下次读回时被判 corrupt | 插件已自动补；如果宿主报会话 corrupt，那是宿主的日志持久化层，不是这条插件的问题。 |

## 6. 个人秘书会话

| 码/状态词 | 现象 | 原因 | 该怎么办 |
| --- | --- | --- | --- |
| `sessions.retain: unknown session` | 单击悬浮球/按 Ctrl+Alt+A 后页面不动，DevTools 里能看到这句（`src/session-log-guard.ts:69`、`src/client/sessionFocus.ts:7`） | 固定秘书会话的 id 已不在宿主会话表里（会话日志被离线重写成不可读回的单帧、或会话被删） | 客户端会先问宿主再决定：问得到「在」就退避重试到 ~20s；问不到就**重建一条新会话**并把 state 指过去（`src/client/secretary-open-recovery.ts:72-95`）。自己修的路径：控制室「个人秘书」卡片 → 更换会话 → 选一条宿主能读回的会话。**别去手工修那个 id**。 |

| `invalid-session-id` / `invalid-card-key` / `invalid-mark` / `invalid-quote`（400） | 已读卡/引用卡操作报错 | 参数校验（`:965`、`:1147-1149`、`:1231-1252`；`assistant-secretary-history.ts:159`） | 刷新页面重来；别自己拼 URL。 |
| `no history source on host` / `history-read-failed`（500） | 秘书历史面板空或报错 | 宿主没给历史源（`src/assistant-secretary-history.ts:131`、`:198`） | 重启宿主；确认这条会话在宿主会话表里存在。 |

## 7. 朗读 / 语音

| 现象 | 原因 | 该怎么办 |
| --- | --- | --- |
| 朗读按钮标红、正文仍在，日志里 `找不到装了 edge_tts 的 python（候选：…）` | 没有装了 `edge_tts` 的 python（`src/assistant-tts.ts:93`） | 在电脑上 `python -m pip install -U edge-tts`（版本必须 ≥ 7.3.1；直连不通就用自己的 PyPI 镜像）。设 `ASSISTANT_TTS_EDGE_PY` 指到那个 python。 |
| 朗读失败但请求到了 Bing 才红 | edge 7.2.x 的 Sec-MS-GEC/DRM 已过期，Bing WSS **403**（README「朗读（秘书卡片）TTS 运行时」） | 升级 edge-tts 到 7.3.1 起。插件不会静默换引擎，所以红就是红。 |
| `text 不能为空`（400）/ `POST only`（405） | TTS 路由参数（`src/assistant-tts.ts:428-431`） | 界面上按朗读，不手发。 |
| 需要代理才能合成 | 默认**不走**代理（`ASSISTANT_TTS_EDGE_PROXY` 不设就是不设） | 明确需要时在本机环境变量里设它；不要写进配置文件。 |

## 9. 拿诊断包的口径
